# 以已发布 0033 为基线收敛迁移

## 支持边界

最终公开版本为 `0034`，所有版本识别、结构创建、数据转换、备份、校验与事务回滚由 Rust 执行。Python 启动入口仅调用原生接口。

- 真正空库直接创建最终结构。
- 已发布的 `0033` 数据库直接升级到最终 `0034`。
- `0001`—`0032` 在业务数据库变更前拒绝，提示先安装 `v0.23.1` 并完成升级，再安装本版本。
- 未识别的版本及无版本但已有业务表的数据库拒绝转换。
- 开发期 `0034`—`0039` 无需转换兼容；同号旧 `0034` 不能仅凭版本号当成最终结构，需要校验关键结构特征。

## 阶段一：冻结验收基线

来源标签为 `v0.23.1`，提交 `4b874083bf9cc4cbc76f9e1c5a51ed7fdd4839ad`，源码中的公开迁移终点是 `0033`。由该标签的实际历史迁移生成：

- `tests/fixtures/rust_store/v0.23.1.sql`：空库的完整 DDL。
- `tests/fixtures/rust_store/v0.23.1.json`：源码提交、逐文件哈希、DDL 哈希和列契约。
- 对象数：36 张表、37 个索引、15 个触发器、0 个视图。
- DDL SHA256：`17439431052edaf315d5411835b92c94108aff03fdbf33e2e27eaca0bb8278df`。

该 DDL 按 SQLite 对象类型和名称导出，测试通过 `schema_contract.load_schema` 按依赖顺序加载，再显式写入版本 `0033`。

生成时使用已有 `capture_baseline.py`，在隔离临时目录展开标签源码，并明确将 `PYTHONPATH` 指向该源码。脚本核对实际导入路径，执行 `0001`—`0033` 的冻结源码后检查完整性与外键；这些历史 Python 实现不进入生产迁移。

收敛前最终结构与业务行为的参照为 `next` 提交 `de680a67f2f291825b65551efdf41908b16c68dc`。旧开发版本号 `0039` 只用于定位参照，不属于新的支持入口。旧的 `main_0033.sql` 和 `v0.22.0.sql` 继续保留其真实来源，不改写成 `v0.23.1`。

## 分阶段交付

1. 固定真实 `0033` 结构、数据场景和最终结构契约。
2. 解除空库初始化及私有补丁对历史链的依赖，删除 `0001`—`0032` 迁移和专用过程测试，加入旧库拒绝规则。
3. 收敛最终表、索引、触发器与直接建库逻辑，独立验收结构生成。
4. 收敛 `0033` 业务转换并接入最终结构，统一为 `0034`。
5. 收拢调用、夹具、文档和构建声明，使用实际 wheel 完成公共及私有发行层验收。

每阶段同步调整直接相关测试，交付独立 diff、代码净增减和验证证据；阶段二必须先承接必要依赖，避免删除历史链后空库无法初始化。

## 最终结构验收

空库创建与真实 `0033` 升级后的受管结构应一致。核对表与列、类型、空值、默认值、主键、唯一约束、外键、索引与触发器语义，避免只比较表数量或逐字比较 SQLite 的建表 SQL。声明了顺序契约的列和输入集合继续验证顺序。

直接创建最终五表增量分析模型、队列字段及最终触发器；不创建随后又删除的十九张分析派生表、贡献中间表或历史隐藏字段。非本项目管理的表、索引和触发器保持原样。

## 业务事实与失败验收

- 保留账户、组合、执行及关联记录的身份、归属、原生订单和成交编号、费用依据、资产、目标、审计、冻结通知与原始未知值。
- 分别验证 SQL NULL、JSON null、字段缺失、空集合、大整数及数值边界，不通过权重或价格反推缺失业务事实。
- 仅移除能由完整规范事实重建的执行摘要。孤儿摘要、独立对账字段或矛盾事实阻止升级，并回滚整个事务。
- 升级前备份必须包含已提交 WAL；备份失败时不开始转换。迁移及版本写入使用同一事务，坏 JSON、事实校验失败和提交前失败均保持原结构、事实、缓存与版本不变。
- 可重算的旧分析缓存丢弃并安排重算；重复升级不再次转换业务事实。
- 公共和私有迁移共用事务，保留私有错误码备份及恢复冲突检查，私有码表由发行层提供。

## 回退边界

保留 `0034` 到 `0033` 的显式回退。通过校验后重建旧版可消费的业务文档，不恢复可重算分析缓存和已确认可推导的执行摘要。独立原始材料由升级前备份保存。

无法由旧结构无损承接的 pending 输入、未结算结果或资产阻止降级，失败不改变数据库。回退再升级仍应保留业务事实；版本号、原生能力声明和交付 wheel 必须一致。

- Axon：225 个不同用例分批通过；本次修复后重跑了 30 个迁移测试，并在重新构建及安装的 wheel 上通过产物验收和迁移冒烟检查。
- UI 类型检查和静态资源构建通过；本任务没有修改 UI 交互。
- 实装 wheel 验证了三项目导入路径、原生二进制哈希、静态资源，以及新建、真实 `0033` 结构升级、事实读回、重复升级、降级重升和旧版本拒绝。

验收环境为 macOS arm64 / Python 3.12。三个第一方包均从候选 wheel 安装到独立环境；第三方依赖复用本机已经安装的固定版本。没有执行全量 Axile 回归、Linux 兼容性验证、真实数据库升级或公开发布。

`0034→0033` 保证旧版可消费的业务文档；恢复的 `raw_input`、`raw_result` 和 `assets` 列仍沿用既有回退行为，位于表末尾并带 `{}` 默认值，不承诺还原原列序或原始 SQL 文本。
