# Python 日志热点优化（2026-10-27）

保留 Python 读取、校验、排序、过程树和证据收集，优化时间显示、重复正文展开和预算检查。没有切换 Rust 读取器或增加依赖。

- 时间前缀用固定数字格式化替代系统 strftime；单次批量调用只缓存当前绝对秒，缓存不会随记录数增长。
- 模板字段在定义阶段校验后由当前解码器复用；受控批量显示复用已生成正文，旧版字典和外部可变记录仍按当前字段解释。重复记录仍比较完整的展开结果。
- JSON 大记录继续逐块编码，字节累计保持精确；每条记录及最多 64 KiB 或剩余额度检查预算、取消和超时，不先构造完整的展开 JSON。已有的正文预检查、无效记录回滚和逐条脱敏保护一并保留。

## 同批修改前后比较

同一份冻结的 6,098 条数据，包含 raw/gzip、3 个运行、嵌套过程、累计计数、旧版字典和重复材料。证据匹配 4,613 条。每类各做五轮独立进程，前后交替；CPU 为工作阶段 user + system，耗时包含读取及相应展示/收集，内存为工作完成时整个进程峰值 RSS，包含导入。前后全部输出哈希相同。

| 场景 | CPU ms：前 → 后 | 耗时 ms：前 → 后 | 耗时减少 | RSS MiB：前 → 后 |
|---|---:|---:|---:|---:|
| 原始读取 | 106.98 → 96.62 | 108.78 → 97.30 | 10.55% | 120.84 → 120.73 |
| gzip 读取 | 106.60 → 99.47 | 107.59 → 100.04 | 7.02% | 120.77 → 120.81 |
| 时间线 | 720.18 → 114.70 | 726.23 → 115.57 | 84.09% | 123.67 → 123.73 |
| 过程树 | 723.83 → 123.68 | 728.97 → 124.44 | 82.93% | 123.91 → 123.91 |
| 证据收集 | 687.07 → 394.61 | 692.87 → 397.60 | 42.61% | 116.94 → 117.44 |

内存中位数变化不足 0.5%，各自范围重叠，判为基本持平，不能宣称显著减少。原负载的时间戳集中在同一秒附近，批量时间缓存命中率较高，不能将这里的倍数当作生产保证。

## 时间分散补测

将同一份数据的 E 时间偏移改成 `(seq * 3 + run_index) * 1_100_000` 微秒，覆盖数千个不同秒，不覆盖原始数据。补测同样五轮交替进程，前后输出哈希一致。

| 场景 | 耗时 ms：前 → 后 | 耗时减少 |
|---|---:|---:|
| 时间线 | 721.41 → 398.44 | 44.77% |
| 过程树 | 725.86 → 404.74 | 44.24% |

证据计费的性能剖析显示，同一原始负载的预算检查次数从 1,077,690 次降到 21,672 次。Profiler 数据只用于定位调用次数，不作为上表耗时。
