# 宏源 #69：报撤监测与非法合约校验

本次对应讨论中的第 2、4 项，即原报告「程序化 2.3.1 第4点」和「外接 2.2.3.2 第2、3、4点」。代码改动及离线验证不表示宏源柜台验收通过。AppID 与持仓明细接口不在本次范围。

## 报撤统计与预警口径

界面明确区分原有本地风控额度与新增原生调用监测：

| 指标 | 定义 |
| --- | --- |
| 报单调用 | 已接入记录器的普通 CTP `ReqOrderInsert` 调用，取得同步返回后计一次；返回非零也计入，并单列同步拒绝 |
| 撤单调用 | 已接入记录器的普通 CTP `ReqOrderAction` 调用，规则与报单相同；不表示撤单成功 |
| 报撤合计 | 上述报单调用与撤单调用之和 |
| 待确认 | 仅持久化了调用前事实，或调用异常、结果更新失败；不推定已发送，也不推定为零调用 |
| 本地额度 | 保留原本的风控放行计数；本地校验失败或下游拒绝仍可占用额度，与监测阈值独立 |

本地拦截不产生原生调用记录；查询、认证、回报重放及外层 `cancel_order` 包装不重复计入。原生 API 返回 0 不代表柜台／交易所受理，更不代表成交。柜台订单回报仍独立保留，撤单记录不会覆盖报单的回报关联。

窗口是保存监测配置时的账户时区自然日，不冒充 CTP TradingDay。仅覆盖接入后的主程序和脚本入口；其他终端、未接入脚本、启用前历史、期权行权及其撤销不在范围内。不能把该指标当作柜台全账户委托总量。

报单调用、报撤合计各有一个独立正整数阈值，默认留空关闭。达到阈值的当笔同步结果与预警在同一 SQLite 事务提交；预警保存账户、指标、配置版本、自然日、时区、触发数字／阈值、时间、调用及 execution 关联。并发调用、重复回报、重启和页面刷新不会重复生成同一版本同日同指标预警。

降低阈值、重新启用和修改时区会保存新版本并立即重评估当前窗口；重复保存相同设置不创建新版本。禁用或跨日不沿用上一窗口的活跃提示。存在待确认调用且已确认次数尚未达值时，返回未知状态；已确认次数本身达值时可明确预警，待确认数仍单列。

配置及查询：

- `GET /api/v1/account/{account_id}/orders/monitor`：当前窗口、阈值、状态及持久化触发事实。
- `PUT /api/v1/account/{account_id}/orders/monitor`：完整保存 `order_limit`、`combined_limit`；`null` 关闭，正整数启用。
- 既有 `/orders/submissions?control_date=YYYY-MM-DD` 流水增加 `operation`，旧流水缺少该字段时兼容为报单；报单汇总字段保留，撤单单独增加字段。
- SSE 流控快照增加 `submission_monitor`，账户流控摘要提示达值，弹窗可配置并核对触发时数字。

需要先执行新增数据库迁移 `0033`。本次未操作运行中的数据库或连接柜台。

## 非法合约发送前校验

下单、订阅整批、撤单、订单／成交查询及行情快照入口先检查格式，再检查会话、补齐目录、检查行情和发送。请求构造函数及 TraderApi 统一发送边界再次校验，避免绕过业务入口后先得到缺失行情错误。

非法换行、回车、空格位置、特殊字符和超长输入返回 `CTPInputValidationError`。不通过裁剪、去空格等方式修改交易标识。合法期权与套利组合原样保留；组合自身的合法分隔空格不一概拒绝。仅明确支持全量查询的入口允许空合约。

离线回归验证非法输入对应的目录补齐、SDK 查询、行情订阅与报单均未调用；SDK 替身验证普通报单与撤单只产生一次调用事实。SQLite／HTTP 回归覆盖当笔到值、同步拒绝、未知结果、重复回报、并发、重启读取、跨账户、跨日、阈值调整及迁移。

遵照用户要求不进行浏览器验证。真实柜台复测仍需另行保留时间戳、实际输入、原生请求零发送日志和合法合约对照，再回填原报告；目前未取得原报告正文，不在此记为通过。
