# Axile 0.25.0 Alpha

首个版本为 `0.25.0a1`，后续按 `a2`、`a3` 递增。同名 `axile` 包发布到 PyPI；`main` 继续维护稳定版，`next` 承载预发布版本。

## 本次变化

- Rust 原生存储与增量绩效分析。
- 执行录制与浏览器回放。
- 组合数量目标及持仓对照。
- 算法工作台、自定义算法目录和按时段选择算法。
- 账户和组合归档、复制。

Alpha 阶段接口和行为仍可能调整。先验证自己的渠道、组合和算法，再决定是否用于实际账户。

## 安装范围

首版提供 Linux x86_64、CPython 3.12 及以上的 wheel，内含原生扩展、Web UI 和回放 WASM。发布时以 wheel 标签为准，Linux 发行版仍需满足其 glibc 要求。暂不发布 Windows、macOS、其他架构 wheel 或源码分发包。

在独立目录创建虚拟环境后安装：

```bash
uv venv --python 3.12
uv pip install 'axile[tqsdk]==0.25.0a1'
uv run axile
```

CTP、掘金分别替换为 `axile[ctp]==0.25.0a1`、`axile[gm]==0.25.0a1`。首次完成初始化后按提示重启。预发布采用明确版本安装，普通稳定版用户无需切换。

## 试用旧数据

1. 停止原服务和关联 worker，备份配置、数据库及需要保留的录制文件；在线文件复制可能遗漏 WAL，不能把它当成完整备份。
2. 在独立目录使用备份副本，核对配置中的数据库路径、定时执行开关和通知配置，避免同时启动两个使用同一账户的服务。
3. 已发布的 `0033` 数据库可升级至本版 `0036`。更早的数据库先用稳定版升级至 `0033`；开发期中间结构不承诺兼容。
4. 新版迁移清理旧绩效缓存并重新计算，首次完成前可能暂时没有绩效图表。核对账户、组合、历史执行和资产记录后，再验证渠道与算法。

降级是显式数据库操作，可能因新增数量目标、归档状态或无法无损承接的事实而被拒绝。仅安装旧包不会回退数据库。需要恢复升级前状态时，先停止所有进程，同时处理数据库的 WAL/SHM；备份不含升级后的新记录，不能覆盖仍需保留的数据。

## 发布检查

全量 Python 回归、覆盖率检查、CTP 离线场景、Rust 和前端单元测试在本机运行。GitHub Actions 保留原生与前端构建、静态检查和少量启动/迁移/API 冒烟。发布 workflow 复用同一提交已通过 Code Quality 的原生扩展与前端产物，避免重复编译，并对实际修复后的 Linux wheel 做隔离安装，校验原生能力、迁移和静态资源后才上传 PyPI。

发布版本和锁文件先通过 PR 合入 `next`，确认该确切提交的 Code Quality 成功，再给同一提交打 `v0.25.0a1` 标签。`release.yml` 支持手动构建演练，手动触发不会上传 PyPI。正式标签触发构建、安装检查和发布；PyPI 验证成功后，GitHub Release 标记为 prerelease。
