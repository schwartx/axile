# 期货平仓规则

账户的「执行算法」页面通过文字摘要与齿轮打开平仓设置。弹窗的「完成」只修改页面草稿，页面「保存」后用于后续执行，在途执行使用原快照。常规调仓与清仓共用配置。

CTP 默认「按品种规则」，可以切换「低手续费优先」；TQ 仅提供「按品种规则」。品种规则依次使用人工覆盖、程序预设和账户默认顺序。删除人工覆盖即恢复预设，人工覆盖持续到用户恢复。

品种键只包含大写字母：`AG2611`、`ag2612` 都使用 `AG`。普通期货的三位、四位年月后缀均可识别，期权与组合代码不套用此提取方法。顺序偏好不改变交易所的报单能力：上期所、能源中心分别提交平今和平昨，其他交易所提交普通平仓，由交易所决定扣减顺序。

## 预设维护

真源为 `axile/executor/futures_close_presets.json`，包含版本、说明，以及每个品种的顺序、平昨手续费说明和平今手续费说明。首版顺序采用先昨后今基线，不承诺最低费用；目录来自仓库已有期货时段表。手续费说明全部为 `null`，等待维护者补充，空白不代表零费用。说明可以使用元/手、按成交额比例等文字；补充后随版本发布，并更新预设版本。

预设说明不作为账户实际费率，不参与自动费用比较。更新预设只影响未被人工覆盖的品种，历史执行证据保留当时的预设版本与实际计划。

## 自动费用比较

CTP 查询当前账户、实际月份合约的平仓和平今费率，费用比较不连接行情。按金额费率与按手费用分别按相同单位比较：两项相同则费用相同；一侧两项都不高于另一侧且至少一项更低，则优先该侧。如果按金额费率与按手费用的高低相反，无法脱离成交额判断，使用品种规则兜底。

明确的零费率有效；缺失、无效、溢出、超时和额度阻止不能转换成零。费用相同或无法比较时使用品种规则。费用查询使用账户的控制及节流，缓存按账户实例、交易日、合约隔离。换日清除缓存，每次执行重置失败缓存；重建连接实例后重新查询。

审计事件 `futures_close_planned` 记录规则来源、预设版本、实际费率、查询时间、兜底原因与拆单计划；纯按手计费还记录每手费用。执行详情直接解释该事件。终止、会话失效、持仓不明或冻结量无法分配不会按费率缺失处理；保持原来的拒绝或终止边界。

## 配置与迁移

账户字段 `futures_close_policy` 包含 `mode`（`rules`/`fee`）、`fallback`（`yesterday_first`/`today_first`）和 `overrides`（字母品种到顺序的映射）。TQ 请求 `fee` 会被拒绝。新配置贯通账户 JSON 设置、公开响应、执行快照、worker 和清仓输入。

0029 迁移删除算法及合约交易规则里的旧 `offset_priority`，归并到新配置。同品种月份规则冲突、主交易与清仓规则冲突时，在写入前报告账户编号并停止迁移。旧的全局先今后昨被展开为本版品种覆盖，保留原选择；历史执行记录不改写。

迁移保存执行设置的前后快照，未修改执行设置时可以无损降级；升级后产生无法表达的新设置时拒绝降级，避免静默丢失配置。请使用升级前备份恢复此类数据库。
