2026-11-15。Axile 基线 `349eecc68c3bd32f18d88d1acb364375af769951`，分支 `codex/replay-single-source`。提案未改动。本记录继续[首个原始预览检查点](raw-replay-checkpoint.md)，不表示提案整体已经交付。

后续订单、持仓推导及执行汇总进度见[新检查点](raw-replay-derived-checkpoint.md)。本文保留当时的验证边界。

## 本轮接通的范围

浏览器现在按固定身份批次求值并显示稳定成交、弱身份成交和命令观察，每页至多 8 项。稳定成交按不透明的 `trade_key` 合并；未强制它使用 JSON 数组格式。物理事实冲突、归属冲突、缺失或非法数值有明确状态；未知不会显示为零。弱身份仅使用明确的 `related_capture_seq` 关系。命令的合并不能使撤单操作变成下单归属证据。

持仓基线归约内核已实现并通过单元测试，页面入口尚未交付。它按字段合并：缺省和 null 保留既有值，显式 missing/invalid 使字段未知，known 可以恢复；完整范围中的缺席只将已观察字段置零。quantity、today_quantity 等各自保留证明出处，一次仅更新今仓的观察不替换总数量的证明。证明描述只留下有界的标量元信息，不保留成员数组或错误类型中的嵌套对象。

页面明确显示账户录制段的原始业务观察，执行归属列仅展示原始执行标识。尚未用命令关系补全执行归属，未提供订单完整状态、观察后成交的持仓推导或完整区间统计。

真实录制包含 2,583 条账户范围持仓观察。末尾持仓基线尝试未在现有索引预算内完成，不能算作任意时间跳转通过，已关闭这个未验收的页面入口。流发现已从扫描整个历史的 DISTINCT 改为按流跳转；SQLite 中止会保留原始预算/取消原因。完整的持仓批量读取、规划成本和跨目标状态复用仍须继续实现及验收，没有通过放大预算或静默截断绕过问题。

## 索引与读取

`.replay-v2.sqlite` 增加直接身份字典、原始行/块位置、直接关系、范围引用、代次/查询引用及证明成员位置。它不保存合并后的订单、成交、持仓数量或统计值。观察业务载荷仍只保存在原始压缩 MCAP 中。

新查询包括 objects、object-streams、object-blocks 和 members。身份页最多 8 项，块页最多 16 项。引用但尚无原始观察的身份不会出现在业务对象页。证明成员以原始证明序号、行位置和原始 canonical trade key 查询，返回原始成员位置；必须先存在已发布的证明，才能返回成员不存在。Worker 仍须验证原始证明后才能使用负结果；本轮没有据此输出持仓完整性结论。

冻结源现在同时绑定 index_generation、recording、commit_id 和 through_seq。静默推进水位会产生新的 commit_id。目标时间以该提交的水位为界，不借用后来提交的水位。代次验证在数值身份、块 ID 和成员查询之前进行；页面重建会话时清掉旧分页游标。

业务读取先分页预检一个有限阶段的块目录，只累计标量估计，再重新分页执行。Worker 为每条流只保留当前解压块，按捕获序号合并输入；一个批次顺序归约身份前缀，不因每条事件缓存未命中而从头重建。没有整段历史数组、全局 seen 集合或常驻的完整计划。

市场原文及时间索引保留。本轮不建立尚未被求值器使用的市场逐笔身份目录；实测这个额外目录会显著增加索引体积。市场去重/统计需要配套实现自己的批次求值和必要索引，再通过新代次发布。

## 固定资源边界与取消

- 每批至多 8 个身份、16 条输入流；WASM 硬上限 32 MiB。
- 压缩缓存载荷最多 4 MiB、4,096 项；缓存键长度有界。主线程只查当前需要的缓存项，不接收完整缓存目录。
- 每条流只持有当前解压块；原文块最多 512 KiB 加换行。Worker 每次最多消费 16 条观察再让出事件循环。
- 结果最多 8 个对象，WASM 输出序列化结果最多 256 KiB。页面保留当前展示批次，不保留翻页历史。
- 原有服务器根任务、账户速率、并发、索引指令和响应预算继续生效；目录预检和第二次遍历也计入原根任务。

取得位置后先关闭索引事务，再读取原始文件，避免慢文件 I/O 固定 WAL 快照。已经压缩的原始块声明 identity，防止 HTTP gzip 再压缩浪费 CPU。发送端每个 64 KiB 片段检查取消和期限，并使用 2 秒无进度超时；持续推进的响应不因总发送时间超过 2 秒而被截断。发送停止后清空响应体，再释放额度。根任务的 30 秒期限仍有效。

主线程对 Worker 请求设 5 秒看门狗。失败或取消时终止 Worker，清理回调和计时器，取消网络，并完成原根 seal/ACK；同步 postMessage 失败也走同一清理路径。取消时已发生的读取不从账本扣除。丢失 ACK 只重试控制请求。实例丢失、回执明细丢失的自动恢复仍未交付；当前明确失败，不报告虚假的零成本。

## 显式离线重建

`scripts/rebuild_raw_replay_index.py` 仅接受当前 v2 原始 MCAP；没有旧格式读取或转换入口。普通读取遇到旧索引布局会要求显式重建，不启动解压或扫描任务。

重建先获得读取执行体锁及该账户的 capture writer 锁，逐记录流式核验原始数据、校验和及 durable commit。只发布完整提交前缀。暂存 SQLite 完成后恢复 WAL 模式并关闭、同步，再原子替换，生成新的 index_generation；后续追加不需要在历史读取期间切换日志模式。原始 MCAP 不改写，commit_id 保持不变。重建失败保留已发布索引。在途读请求或录制仍持锁时明确拒绝，不能用重建抢占生产任务。

## 实测

本机样本沿用首轮离线抽取的原始观察：真实数据 4,820,994 条，另有 50,000 条压力观察。原始采集字段已经过先前渠道的规范化，不能用它证明所有新采集语义。未调用旧投影引擎作对照。

同一组 4,870,994 条观察的候选市场身份索引为 1,224,212,480 字节；移除本轮未使用的市场身份目录后，索引为 **451,346,432 字节**。最终离线重建耗时 **95.78 秒**、CPU **88.62 秒**、峰值 RSS **119,013,376 字节**。重建前后两个原始 MCAP 的 SHA-256 相同。这是受控维护成本，不是普通回放请求成本。

真实录制的固定 242 个目标每个各自完成一个根任务，按此前固定的游标核验盘口和证据序号。此次每个目标还请求首批稳定成交，检查对象上限、观察序号边界和原始成交值，并逐一核验每侧前 20 档的价格和数量。没有把整个录制大小作为读取放大的分母。

| 精确目标 | 242 / 242 |
| 必需的不同原始块 | 2,969 |
| 必需原始块并集 D | 14,643,054 字节 |

逐目标耗时中位数为 230.15 ms，最大 294 ms；API CPU 增量 26.75 秒，峰值 RSS 从 148,799,488 到 148,799,488 字节，结束后活动读取为零。数据响应 17,651,083 字节，原始块和索引响应成本均未因根任务切换清零。

上述测量使用实际组件、Worker/WASM 和生产读取路由；执行归属查询由隔离映射代替。它不等于完整应用导航、实盘并发或公网慢连接验收。浏览器堆读数包含固定的基准记录，不是浏览器进程 RSS 或总内存硬上限。HTTP 头、控制响应和静态产物传输不计入原始块字节；索引响应、索引指令和控制次数另行计量。

1024 个固定浮点输入暴露了默认 JSON 解析的一单位偏差。raw-only WASM 已启用 float_roundtrip，并增加实际错误输入的回归用例；1024 个输入修复后全部原样保留。账户分析的既有默认构建不启用这个新特性。额外增长 32 MiB 的请求被实际 WASM 内存上限拒绝。

同一目标跨 20 个已结算根任务重复读取，第 2 次起原始块读取均为零；会话累计成本仍从 74,096 增至 329,931 字节，未因切换根任务清零。

同源测试脚本让实际 Worker 在已经加载 WASM 工作集的 business-step 阶段持续忙循环。主线程约 5.10 秒后终止它，终止次数为 1；随后显式再次请求同一目标，准确恢复到序号 4,820,989。恢复读取 57,305 字节，包含失败尝试的会话累计成本为 142,440 字节，结束后服务器活动读取为零。
