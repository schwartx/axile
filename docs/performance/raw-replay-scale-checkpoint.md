## 数据与本次结论

本轮同时使用两类输入，不能混称为真实成交：

- 保留原录制 ID 的 4,820,994 条真实观察及其既有盘口期望。另从该 v2 原始文件提取真实数据，经过正式 `ReplayRecorder → NativeWriter` 以 1,000 条/秒录制 600 秒，产生 600,000 条源观察和 19 条正常采集边界/执行观察。新录制由 Recorder 分配新的观察时间和序号，不冒充现场账户。
- 人工扩展业务样本：512、4,096、40,000 个稳定成交身份，各有同数量命令及订单；40,000 样本每份证明包含 20,000 个成员，16 份证明共 320,000 个成员引用。另有 8,192 身份的交错重复观察样本、64 份成员证明及逐字段水位证明；24 品种样本含 4,096 身份、64 份成员证明、交错更新及逐字段证明。数据经正式 v2 writer 写入，无服务端业务投影。

这些输入下的完整统计、订单页、持仓页和精确时间跳转均通过；并发期间没有录制错误、预算错误或活动读取泄漏。内存、根字节数和账户速率上限没有提高。**整体根的索引工作量和时限经过明确调整**，不是沿用上一检查点的所有门槛通过，见下文。

## 发现的问题与修复

初始实现用展示页的 8 个身份作为所有依赖批次大小。4,096 身份的持仓，以及 40,000 身份的订单/持仓，均在约 2 秒触发 `REPLAY_ROOT_INDEX_BUDGET`。原始读取量很小，失败来自过多小批次及原先整个根仅 200,000 工作单位的门槛。

依赖身份页现在最多 128 项，并受 64 KiB 序列化页预算限制；展示页仍是 8 项，订单续算状态及持仓目标仍最多 8 个。WASM 只扩大固定的成交/命令依赖槽，不持有完整身份字典。成员查询使用已校验的对象 ID 直接定位证明成员，减少不必要的 canonical key 查找。20,000 个候选身份、10,002 成员的正/负查询测试核对原始位置，并限制 VM 工作量，防止扫描整份集合。

128 个身份可能跨过 16 条流。客户端在依赖预检返回工作集过大或阶段字节过大时，在**同一个逻辑根**中二分到较小批次，沿用原截止点、预算及 Worker 内标量归约器；不会重置根来消除已经发生的规划成本。单个小批次仍不满足边界时明确失败，不扩成全市场前史。24 品种的真实 Worker 测试覆盖了这条路径。

收尾检查还补了长字段边界：大于 8 个身份的依赖批次另受 256 KiB 保留状态序列化预算约束，每个发生变化的身份更新计数。状态或结果字节超限时，Worker 只释放当前批次，保留此前的标量归约器及压缩缓存，通知客户端在原根中二分；取消、超时和其他错误仍会终止 Worker。128 个身份各含 4,000 字节订单号的真实 WASM 样本触发状态预算，分成 4 批后数量仍为 128，线性内存峰值 2,162,688 B。没有以提高 32 MiB 内存上限来处理宽字段。

冻结录制视图刷新会复用会话、续租定时器和压缩缓存，以新根读取新提交。初始化恢复等待只执行一次；打开会话失败后会清理忙状态，刷新被新目标取消时先结算旧根再运行最新目标。测试覆盖连续刷新、打开失败重试及刷新中跳转，避免长时间运行时不断消耗会话槽。

## 最终固定资源规则

| 项目 | 上限或规则 |
| --- | --- |
| 单次索引读取 | 200,000 工作单位、2 秒索引事务，结束即关闭快照 |
| 整个逻辑根 | 8,000,000 工作单位、60 秒、8 MiB 响应/定位字节预算 |
| 账户 | 保留每滑动窗口 2,000,000 索引工作单位、32 MiB；跨根/会话累计账目不清零 |
| 准入预留 | 按单次读取上限及根剩余额度预留，实际停止后结算；预留也占账户速率额度 |
| 并发 | 全局 4、账户 2、单根 1 条活动读取，控制通道原上限保留 |
| 浏览器 | 压缩缓存 4 MiB / 4096 项；WASM 线性内存硬上限 32 MiB；16 条流头、128 个查询截止点、8 个订单续算状态 |
| 传输与取消 | 每页最多 128 块 / 1 MiB；Worker 每 16 个事件让出事件循环，5 秒主线程看门狗；取消先终止 Worker，等读取停止及 seal/ACK 后开后续根 |

工作单位包含 SQLite VM 指令及紧凑定位解码。诊断测得 40,000 身份的必要元信息处理本身约需数百万工作单位；把原来的 200,000 留作单次读取限制，整体根给出独立有限上限。账户速率、字节额度和并发未放宽，客户端也不会自动换根绕过限流。大计算会等待账户额度，60 秒包含等待时间。这是本轮资源契约的修改，需要在后续验收中继续按该固定契约衡量。

## 业务规模结果

以下顺序运行，后续请求会复用压缩缓存；同时有另一个 Reader 读取真实历史和持续录制。时间包含账户限流等待，不是独立冷磁盘延迟。

| --- | ---: | ---: | ---: |
| 4,096 身份，持仓 | 0.665 s | 176,988 B | 2,031,616 B |
| 40,000 身份，完整统计 | 22.908 s | 2,236,856 B | 2,424,832 B |
| 40,000 身份，订单页 | 31.741 s | 9,665 B | 2,424,832 B |
| 40,000 身份，持仓 | 32.773 s | 0 B | 3,276,800 B |
| 8,192 交错身份，完整统计 | 7.150 s | 799,859 B | 3,276,800 B |
| 8,192 交错身份，持仓 | 9.891 s | 551,512 B | 3,276,800 B |
| 8,192 交错身份，订单页 | 8.723 s | 9,463 B | 3,276,800 B |
| 40,000 身份，跳回中点统计 | 11.569 s | 9,936 B | 3,276,800 B |

逐次核对已知数量、成交额、VWAP、稳定身份计数、完整性、订单剩余量及归属；重复观察不重复累计。持仓覆盖成员不再贡献增量，未覆盖成员贡献增量；总量/今仓达到预期，可用量因未覆盖成交保持未知。中点统计为 20,000 笔、数量 20,000，而非最终 40,000 笔。整组 Reader 的结算累计为 18,096,910 B，包含索引定位和响应成本，不能把后续 0 B 原始下载称为 0 成本。

最终多品种构建还验证了 24 品种、4,096 身份的完整统计、8 个持仓目标和 8 个订单目标，分别耗时 12.799 / 14.181 / 12.778 秒。最大 WASM 1,572,864 B。三个根的结算工作量为 2,179,368 / 2,403,868 / 2,187,468，包含拆分失败预检的成本；原始读取 234,579 / 362,043 / 18,158 B。同一 Reader 连续刷新 7 次仍使用同一个会话。

## 持续录制与读取

一轮录制持续 600.042 秒，接收 600,000 条真实源观察，最终头部为 600,019、状态 `closed`，与 NativeWriter 的实际 append 次数一致。采集队列峰值 217,701 B，低于 8 MiB；单次 observe 最大约 47.2 ms，原生 append 最大约 46.4 ms，poll 最大约 35.0 ms。没有后台 writer 错误，也没有以队列溢出停止录制来通过测试。另一次同样 600 秒的录制基线也无错误，但它不作为并发验收替代品。

浏览器持续 611.215 秒，完成 488 个精确目标，其中 163 个来自原始长历史、325 个来自新录制及其冻结旧提交。约 **474 秒与录制重叠，374 个目标在录制仍运行时完成**；其余继续读取封口后的数据。不能把它写成完整 10 分钟同时并发，更不能称为通宵稳定性验证。

每次核对盘口序号、买卖各 20 档，以及最近 32 条精确观察序号。不断切换新提交和已冻结旧提交时仍保持正确，没有读取到旧游标不应见到的未来观察。耗时中位数 44.5 ms，P95 55.3 ms，最大 8.747 秒；最大值发生在同账户大业务计算争用索引速率额度时。Reader 累计压缩原始读取 16,812,682 B，压缩缓存最大 4,194,301 B，已实际发生淘汰；WASM 最大 1,376,256 B。

该浏览器运行期间，账户全部并发请求累计增加：响应/定位成本 39,324,834 B、原始压缩读取 20,607,295 B、索引工作量 22,489,750、定位载荷 445,068 B、控制调用 1,810 次。这包含上表的大业务 Reader，不能归给 488 个报价目标。累计量超过单窗口额度仍正常完成，窗口限制保留，换根和关闭另一个 Reader 都未清空累计账目。全部完成后服务端活动读取为 0。

每 2 秒采样两个测试进程。录制进程的实际峰值 RSS 约 138.4 MB，采样区间从约 137.0 MB 到 138.35 MB；读取服务采样从约 147.64 MB 到 148.29 MB，最大约 148.34 MB。未见随事件数线性保留的历史状态。WAL 采样峰值 6,567,312 B，读取快照没有长期阻止检查点。录制进程用户/系统 CPU 时间约 166.80 / 4.92 秒；浏览器运行区间服务器 CPU 增加约 27.66 秒，包含测试监控。源速率是加速回灌，不能当作真实账户全天负载。

监控保存了 305 组有效样本；最后一次采样遇到 WAL 文件正常回收，原脚本误以异常退出。观测脚本已改为文件不存在时记 0，既有样本保留，不补造最后一个测量点。录制、浏览器及结算的完整结束证据独立于此采样器。

OS 文件页缓存为热缓存；逻辑原始读取、元信息工作量与物理磁盘 I/O 不混称。RSS 不包含系统文件页缓存。主线程最终 GC 后约 3.24 MB，不包含 Worker/WASM，测试页面也保留了核对结果；它不是浏览器进程 RSS 硬上限。

## 大计算取消及结算

在 40,000 身份持仓推导器已收到第一批成交依赖时切换到最早盘口，旧 Worker 实际终止 1 次。新目标盘口序号为 2，成交页为空，旧结果没有覆盖新目标。

旧根实际结算原始读取 1,270,391 B、响应/定位成本 1,291,148 B、索引工作量 22,463；新根原始读取仅 321 B，成本 2,408 B。包含初始 manifest，最终会话累计 1,299,939 B。失败尝试成本没有丢失，服务端活动读取归零。
