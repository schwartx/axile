## 磁盘结果

同一份真实录制 ID、4,820,994 条真实观察，外加 144 条人工边界观察。原始文件逐字节保持不变；下面的索引及合计均包含两份样本。

| SQLite 索引 | 908,914,688 B | 96,755,712 B |

索引减少 **89.35%**，合计减少 **48.22%**；索引约为原始文件的 **12.48%**。这是该固定样本的结果，不能保证所有事件大小、提交频率和证明密度都有相同比例。

表中按文件字节数比较 SQLite 主文件；最终 WAL 为 0 B，另有 32,768 B 的共享内存文件。没有将离线验证输入、构建缓存及报告混入运行时数据体积。

原索引的 `observations`、`stream_time`、`observation_time` 分别占 321,810,432、277,192,704、267,325,440 B。这三处逐观察存储反复携带完整录制 ID，合计约占索引 95.3%，本轮全部删除。

新索引布局为 `6`：

- 每个不可变定位页最多 256 条观察，观察序号连续，时间、块 ID 及块内行号使用差分变长整数。页头保留首尾序号和时间，时间索引按页建立。这里只存直接定位元信息，不复制业务字段或状态。
- 每个压缩块保留最多 1024 条精确序号/时间定位，块内行号隐含于排列。所选流不在最近证据页时，可直接定位该流的最后一个块，无须扫描全局前史。
- 页和块的定位载荷各附 16 字节 SHA-256 前缀校验。解码严格限制字节数、整数范围、行数及单调性，拒绝损坏、截断、非规范整数和多余尾部，不能把损坏解释成空结果。
- 定位页使用普通 rowid 表。实测 `WITHOUT ROWID` 对此尺寸的载荷产生大量未用溢出页；改用普通表后，定位页由中间版本的 77,942,784 B 降至 27,533,312 B。没有依赖删除后遗留的空闲页制造收益，最终空闲页仅 1 页。

最终主要空间为：`blocks` 49,205,248 B、`location_pages` 27,533,312 B、`blocks_stream_sequence` 8,957,952 B；定位页共 22,319 个，覆盖全部 4,821,138 条观察。没有采样时间或舍弃原始观察。

新录制及显式离线重建共用同一编码器。每次提交最多暂存 32,768 条定位，按观察序号排序并验证完整连续前缀，然后随原始提交发布；安静提交可保持零新增定位页。冻结提交不会被后续定位页改写。重建只处理 v2 原始文件，获得捕获/读取互斥锁后原子发布新代次；运行时遇布局不匹配要求显式重建，不自动扫描原始文件，也不回退旧布局。

隔离样本重建耗时 80.20 秒，进程峰值 RSS 119,111,680 B，用户/系统 CPU 时间约 67.67/7.58 秒。这是离线维护成本，不转嫁给每次浏览器跳转。真实原始文件 775,366,240 B，重建前后 SHA-256 均为 `e3a822727f9e48f0a5d1e06ccaa8727edefe1ede6733d17195b52c8398b25b95`；人工样本 7,090 B，SHA-256 为 `25df4088789737276b19626d49451b7b4dfe635aa9be6ec4da8224b0dcd9d613`。

## 跳转与服务器资源

跳转先按 `(first_time, first_seq)` 定位目标页，再解码固定上限的定位元信息；跨页收集最近 32 条证据，最多检查 32 个页。所选流使用 `blocks_stream_sequence` 查找最后块；若最近证据已包含该块，可直接复用定位，否则只解码该块的定位载荷。业务载荷仍由浏览器解压、归并和推导，服务器不重建持仓、订单或统计。

服务器响应显式选择公开块字段，不把新增的定位 BLOB 传给客户端。新增解码也纳入现有根/账户预算：读取定位载荷先计字节及工作量，再校验和解析；解析失败或取消仍结算已经发生的成本。每 16 条定位检查取消与预算。`index_steps` 现在包括 SQLite VM 指令和定位解码工作单位，不能再把它全部称作 SQLite 指令；`index_bytes` 单独记录定位载荷的逻辑读取字节。

根 30 秒、8 MiB、200,000 工作单位，账户 32 MiB 及 2,000,000 工作单位的滑动窗口等原预算没有提高。账户累计计数跨根、播放段及 Worker 保留。累计 `total_bytes` 包含响应及定位载荷的逻辑读取成本，不能直接称为网络字节或物理读盘字节；原始压缩读取、定位载荷及控制调用另列。

在实际浏览器及正式读取路由中，以预先保存的原始盘口期望验证：242 个顺序目标、24 个确定乱序目标、242 个逆序目标全部成功。每次核对所选盘口的精确观察序号、买卖各 20 档及最近 32 条观察序号，而非只检查接口没有报错。没有遇到预算拒绝后换根继续的情况。

另从空 Worker 缓存单独运行同一组 508 次报价跳转，中间不穿插业务请求。按预先固定目标的所选盘口和 32 条证据定位，离线统计必要压缩块并集，共 2,979 块、`D=14,515,301 B`；分母不是实际下载结果的并集。实际 `R_total=26,924,506 B`，读取放大 **1.855 倍**，重复读取 12,409,205 B。分阶段读量为正序 14,515,301 B、乱序 1,043,239 B、逆序 11,365,966 B；第 60/120/180/508 个目标累计读量为 3,585,490 / 7,502,555 / 10,823,303 / 26,924,506 B。工作集大于 4 MiB 缓存，没有把缓存淘汰的重读隐去。

这组独立序列耗时中位数 62.1 ms、最大 86.7 ms，累计响应/定位成本 30,015,177 B、定位载荷 578,812 B、索引工作量 1,477,736、控制调用 1,526 次，服务器 CPU 约 7.15 秒，结束活动读取为 0。WASM 最大 1,376,256 B，压缩缓存最大 4,194,289 B。该放大值只适用于此固定报价/证据输入范围；业务和取消成本见下文，不把它称为整份提案的全部 R/D 验收。

## 浏览器内存和取消

本轮发现并修复缓存淘汰边界：同一待用页混有新块与缓存命中块时，插入新块可能先淘汰随后才使用的命中块。现在预览和业务分页统一先固定整页的键，再加载缺失块；已有 4 MiB 缓存和分页上限保持不变。客户端测试用 8 个 512 KiB 块填满缓存，再分别验证预览、业务页中新块与最旧命中块共存的场景，确认仅淘汰无关块。

实际长序列已经越过 4 MiB 工作集并发生淘汰，不再只验证完全留在缓存内的短序列。业务与报价混合测试的最大压缩缓存为 4,194,289 B，最大 WASM 线性内存 2,293,760 B；硬上限仍为 4 MiB 缓存、32 MiB WASM。固定身份、流头、查询时点、续算状态以及传输页等上限也未提高。

测试主线程保留了一部分结果供核对，主动 GC 后主线程 JS 已用堆为 2,496,644 B；这不包括 Worker/WASM，也不是浏览器进程 RSS 硬上限。服务器含 FastAPI/原生扩展的峰值 RSS 为 150,634,496 B，不含系统文件页缓存。

在 WASM 业务依赖归约器存在时取消，旧 Worker 实际终止 1 次，新目标正确恢复。取消及恢复合计新增压缩原始读取 175,634 B、响应/定位成本 200,852 B、定位载荷 1,556 B、索引工作量 16,863；失败尝试的实际成本保留，服务器活动读取最终为 0。后续根仍须等待旧读取停止及 seal/ACK 结算，旧结果不能覆盖新目标。
