## 已实现的链路

- 持仓大前缀改为按压缩字节分页、批量二进制读取。每次最多 128 个块和 1 MiB 载荷；按流保留有界待解压页，以固定头部归并观察顺序。没有提高原来的读取、索引指令或 WASM 内存预算。
- 流发现同时返回首批计划，所有流合计至多 128 个描述符；预检后复用这些首批描述符。后续计划分页只保留游标和累计大小，不保留全部历史计划。
- 直接身份查询强制按对象主键定位。实测发现 SQLite 会对 `IN + first_seq` 选择 `objects_page`，导致每批扫描整份身份字典；现在避免这条计划，并用 20,000 个身份的指令数上限测试保护。
- 命令关联由一次昂贵联表排序改成原始提及索引与命令索引的两次定位。命令分页使用 `(first_seq, object)` 游标。持仓证明成员查询可接收同代次的成交对象 ID，避免长 canonical key 撑大请求。所有 ID 仍在源视图及索引代次校验之后解释。
- 布局升为 `4`，新增按流/原始序号定位块及按首次提及序号定位命令的索引。块分页同时定位起点、终点；读取早期时点不再扫描后续块，订单续算也不扫描已经处理的前缀。布局不匹配只要求显式重建，不自动扫描原始文件。

服务器仍只读取压缩原始块及直接定位/成员索引；业务解压、归并、归属、持仓推导和统计均在 Worker/WASM 中执行。

## 业务规则

订单通过完整 place_order 证据补全归属，撤单只影响待确认状态。歧义、冲突和人工/外部归属不会被自动归到当前执行。订单状态归并只请求 `/order`、`/order_set` 和 `/connection` 的相关流，命令与成交由各自有界依赖阶段处理，避免重复解压及超过流数上限。

订单查询的成交围栏取查询观察当时的物理事实，而非最终 T 的成交状态。单批最多 128 个查询时点，只保留每个时点、每个当前订单的标量贡献；超出后续接至多 8 个订单归约状态，继续处理下一段订单历史。查询启动后出现的推送、物理成交变化和更新的完整范围查询会拒绝迟到结果。仅补全成交归属不推进物理围栏；物理冲突会推进。同步代次变化重置该范围的修订比较，并保留账户范围围栏的独立代次。

持仓 quantity、今仓、昨仓、可用及冻结分别保留基线和证明出处。原始成员列表只在原始观察归并时验证，当前观察内的共同证明共享验证结果；不为每笔成交重新扫描整份成员列表。成员正/负查询必须匹配已验证证明及其完整成员数量。覆盖成员可跳过，未覆盖成交才贡献增量；源水位仅对相同来源且 source_seq 有效的事实生效。

增量在固定身份批次间累计标量，全部累计完后再检验最终数量，避免归并次序造成短暂负值而误判。未知方向、开平、来源、弱身份、缺少证明或基线均保留未知。可用/冻结遇未覆盖成交即未知。最终字段互相矛盾时保留观察基线，标记冲突，不输出确定值。若所有字段已不可能推导，停止不再有用的成交读取。

执行汇总固定当前执行、所选品种、录制开始至目标时点及同一个观察截止点。每个稳定身份合并后贡献一次，统计数量、价格乘数量、VWAP、稳定/弱身份数及未知/归属不明数；不平均各页 VWAP。首次观察时间不随后续归属补全移动。归属不明的自有事实先影响完整性，再执行品种和展示过滤；弱身份显式解析后不重复累计。观察结果不足时只展示已确认部分。

这轮没有实现提案 5.8 的全部区间分析：盘口时间积分、市场成交归约及全局统一网格的两遍价格分布仍未接入。现有入口是执行成交汇总/VWAP。

## 取消及资源边界

每个 Worker 保持最多 8 个业务身份、16 条解压流、128 个查询时点、8 个订单续算状态。压缩缓存最多 4 MiB / 4096 项，WASM 线性内存硬上限 32 MiB；待使用压缩页固定并限制字节数，已解压的头部立即解除压缩缓存固定。输出和续算快照均有大小限制。

业务计算每 16 个原始观察真正让出事件循环。主线程继续保持一个运行请求和一个最新候选，取消后先终止持有推导状态的 Worker，再独立完成服务器 seal/ACK；后续根必须等待旧读取实际停止及结算。429 在同一根及 attempt 内等待，不换根刷新预算；源代次或已退休请求不会按限流重试。

当前不支持根内依赖计划就地修订或跨根业务状态增量复用。每个用户请求使用冻结源重新归并有限批次，压缩原始块可跨已结算根复用。预算错误不会自动拆成新根继续；跨根的账户累计字节、索引指令、控制次数及滑动窗口继续保留。

早先离线测试适配器把录制 ID 改成 `real`，却未改查询基准中的录制引用。此次重新生成隔离 v2 样本，保留原 ID `559833787dee4df9be1c5cdeb721b2f5`、观察序号和查询引用；13 份源文件校验值、242 个盘口预期及时间目标均保持一致。转换工具只用于离线输入准备，不进入运行时兼容路径。正常录制和查询仍只接受 v2。
