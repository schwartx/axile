# 原始回放：提案对照复审

2026-11-16，本地 `codex/replay-single-source` 工作树。对照 `/Users/schwarzroot/axon-replay-single-source-proposal.md` 全文，检查服务器读取、浏览器工作集、精确跳转、推导、恢复、区间分析及传送清理。提案未修改；没有部署，没有增加样本规模、并发数或长测时长。此前交付及历史测量见 [最终验收](raw-replay-final-acceptance.md)。

## 发现及修复

| 问题 | 修复及验证 |
| --- | --- |
| 以时间定位无法区分同一微秒的多个原始事件 | 定位结果提供前后事件位置，页面保留精确 `capture_seq`。真实页面验证同一时刻断开、重连的正反步进。 |
| 最近证据可能使预览超过缓存预算 | 保留选中报价和精确截止点，按块大小裁掉最老的可选证据，总压缩预览不超过 4 MiB；定向用例验证大事件。 |
| 报价期限不足以证明断线后的有效性 | 点时有效性使用仅含报价及控制前缀的 Worker/WASM 归约；连接代次变化、断线和停采都截断有效区间，重连不使旧报价重新生效。无期限报价只在自身观察瞬间有效。 |
| 持仓覆盖证明可能跨越连接或采集中断 | 持仓依赖纳入连接、采集控制；中断使证明失效，保留已观察基线，推导字段恢复未知。水位证明不能覆盖尚未解析的弱成交。新有效持仓观察才能恢复证明。 |
| 统计完整性与选中品种、采集覆盖不一致 | 先按品种与时间过滤；已知其他品种的未归属成交不污染当前范围，未知品种仍保守处理。控制前缀单独验证自有成交的采集时长。 |
| 同一读取实例的恢复可被客户端低报水位或无效请求破坏 | 先校验原任务、尝试、预算类型和封口状态，再替换会话；服务端已知成本及耗时取不低于原值。无效恢复保留原会话。 |
| 响应丢失的保守预留与精确回执混用 | 分别保存精确水位和保守预留；后续精确回执可替换预留，但不能退回已确认成本。批次拆分和恢复继续属于原任务。 |
| 页面缺少提案要求的历史图形，直接展开历史会破坏内存边界 | 时间图形最多 128 桶，每个报价样本最多每侧 8 档；成交展示有界桶聚合，订单最多 8 个对象、每对象 16 个观察点。断线留下空白，图形不补造状态；点击或键盘选择后按原始目标重新求值。 |
| 没有报价流的业务无法从页面选择品种 | 目录最多返回 128 个品种并标记是否还有更多；额外品种可直接输入。订单及零成交统计的实际页面用例通过。 |
| 稳定身份通过弱观察获得订单关联时，命令依赖可能漏查 | 命令查询沿已知弱关联寻找订单提及，并应用观察截止点；不读取未来关联。定向用例覆盖稳定观察省略订单 ID 的情况。 |
| 清理文件改名与索引提交之间缺少目录持久化 | 删除临时文件改名及回滚改名后同步目录，再继续索引事务。重新构建本地原生扩展后，传送及中断清理定向检查通过。 |

## 读取规划与累计成本

原有任务、速率、并发、缓存和重试上限保持不变：单点 8 MiB / 8,000,000 索引工作单位 / 60 秒；区间 128 MiB / 16,000,000 / 120 秒；WASM 链接上限 32 MiB，压缩载荷缓存 4 MiB / 4096 项，派生恢复点和主线程结果缓存各 1 MiB / 8 项。

统计、订单和需要成交依赖的持仓先遍历有界身份页，规划整项依赖。最初逐批重复查询完整依赖的实现，在已有 40,000 身份样本上耗尽 8,000,000 索引工作单位，已修复；没有通过提高预算绕过失败。

单点业务任务先按流索引枚举提交截止点之前的非报价、非市场成交业务块，只保留页和计数。如果整个业务前缀不超过 4 MiB / 4096 项，则第二遍将它装入现有压缩缓存，校验后固定到当前根任务结束。后续业务批次共享这些载荷，新根任务解除固定但保留有界缓存。更大前缀沿用分批依赖规划与流式计算；超预算明确拒绝，不能报成计算成功。点时报价检查与完整区间不固定这个业务前缀，避免挤占其流式工作集。

规划身份页只传递序号和身份 ID，实际计算页另带键，避免重复返回大段对象封装。查询、规划、两遍计算、批次拆分和同根重试全部计费。`dependency_plan.raw_bytes` 是计划覆盖的压缩载荷；`index_step_limit` 是规划后剩余的服务端硬工作上限，**不是精确的索引耗时预测**。成员查询数及折叠数用于报告依赖工作量；运行仍受服务端逐次、逐根和账户上限约束。

上述策略以较大的首次业务前缀读取换取后续稳定复用，不声称每个冷请求读取更少。资源可控也不表示无限多次交互的累计读取为常数：会话/账户计量跨播放段保留，速率和并发持续限流；单个任意时间目标仍须在任务预算内完成，超过预算须明确报告。
