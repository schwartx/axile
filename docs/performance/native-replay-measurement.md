# 结构化 SQLite 与 Rust 回放测量

2026-10-20，Linux x86_64，一次隔离合成数据测量。用于验证原生回放计算边界，不代表生产服务整体节省同等内存。该组数据测量单独的回放命令，没有覆盖后来增加的源成本事实、JSONL 发布和规范化结果落库；下述数字不能直接作为完整发布链路的验收结果。

## 测量方式

`scripts/benchmark_native_replay.py` 先建立临时 SQLite：10,000 条按小时递增的观测，每条 10 个品种，共 100,000 条品种事实，数据库 6,991,872 字节。全部为合成完整数据，有明确价格、资产、目标权重、数量和换算单位，没有原始 JSON、未知字段补零或缺失数据填补。

随后启动两个全新进程，读取同一份已提交数据，计算 `30`、`90`、`all` 三个区间及独立权益回放，输出完整 JSON：

- Python 直接通过 `sqlite3` 读取结构化事实，重建完整 `Observation` 历史列表，调用现有 `calculate_performance()`，再序列化响应。这是去除了原始 JSON 解析和 ORM 的 Python 计算对照。
- Rust release CLI 直接读取同一数据库，通过游标逐条消费观测，保留当前持仓及每日输出，并序列化响应。

墙钟时间包含启动、Python 导入、读取、三个区间计算和序列化。每个子进程硬超时 20 秒。使用 `wait4()` 获取各自的 OS `ru_maxrss`，覆盖整个进程，包含原生分配；不是 `tracemalloc` 或仅 Python 对象大小。Linux 的值由 KiB 转成字节。控制进程及最终输出比对不计入两者。

## 本次结果

| 10,000 条观测、10 个品种 | Python 对照 | Rust release |
|---|---:|---:|
| 启动至输出结束 | 1.986 秒 | 0.150 秒 |
| 整个子进程峰值 RSS | 185.70 MiB | 18.56 MiB |
| 用户态 CPU 时间 | 1.776 秒 | 0.136 秒 |
| 内核态 CPU 时间 | 0.208 秒 | 0.012 秒 |
| 输出字节 | 252,837 | 252,869 |

Python 内部计时：导入 0.888 秒、读取和重建观测 0.184 秒、计算 0.597 秒、序列化及输出 0.004 秒。Rust 暂未插入分阶段计时，不能从整体时间推断各阶段单独收益。

完整输出按字段递归比对：键集合、列表顺序、空值、布尔和整数字段一致；浮点使用相对和绝对 `1e-12` 容差，最大绝对差为 `4.440892098500626e-16`。结果不是逐字节相同，浮点文本和末尾换行造成输出字节数差异。

为说明导入基线，另外使用相同脚本运行 1 条观测、10 个品种：Python 峰值 146.14 MiB、1.313 秒；Rust 峰值 15.88 MiB、0.003 秒，输出同样通过比对。大部分独立 Python 进程开销在只有一条数据时已经存在。因此不能把 185.70 与 18.56 MiB 的差直接当作现有 API 进程的增量节省；不同运行的峰值差也不是精确的对象分配量。

## 复现

使用已有依赖的 Python 3.12 环境及预先构建的 release 二进制，无需启动 API 或连接真实数据库：

```bash
PYTHONPATH=. python scripts/benchmark_native_replay.py \
  --binary rust/analysis/target/release/axile-analysis \
  --output /tmp/native-replay-measurement.json

PYTHONPATH=. python scripts/benchmark_native_replay.py \
  --observations 1 --output /tmp/native-replay-baseline.json
```

脚本不构建二进制、不安装依赖、不读取真实历史，临时数据库运行后自动删除。报告保留字节值、CPU 时间、Python 分阶段时间和比对容差。

## 适用范围

这次只证明固定合成数据上的回放输出兼容，并表明独立原生工作进程的开销较低。只运行一组大数据与一组基线，没有重复统计或冷缓存控制，不能据此承诺吞吐、P95 或生产扩展上限。Rust 每日输出仍随历史天数增长。

完整发布链的后续合成测量见[结构化分析完整发布链测量](structured-publication-measurement.md)，包含 Python 与 Rust 同时刻的合计 RSS、JSONL 暂存、SQL 成本复制和三次实际发布；该报告单独列明所测二进制校验和与未覆盖范围。

本次回放测量尚未测量实际 API 加原生工作进程的合计峰值、分析期间账户列表尾延迟、并发写入时 WAL 增长、快照发布落库和真实历史分布。完整服务器仍需 Python 及其依赖，不能把此处独立 Python 对照进程的导入内存计作可全部移除的常驻内存。
