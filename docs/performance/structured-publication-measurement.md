# 结构化分析完整发布链测量

2026-10-20，Linux x86_64，Python 3.12，release 原生程序 SHA-256：

```text
65310c74236b7965ec6cb2ab0c61885f68bc80d9719b605387465a1459d88428
```

这次测量包含 Python `AnalysisManager`、Rust 子进程、JSONL 磁盘暂存、Python 类型校验、规范化结果写入、成本 `INSERT ... SELECT` 复制和旧快照清理。它补充[第一阶段独立回放测量](native-replay-measurement.md)，两者范围不同，不能直接相减作为整体内存收益。

## 输入和边界

历史脚本：`scripts/benchmark_structured_publication.py`。所测 Python 发布入口已退役；脚本暂保留供 `benchmark_analysis_views.py prepare` 引用旧夹具辅助函数，不是当前版本可运行的发布基准。以下数据仅记录当时的实现。

- 合成 10,000 条按小时递增的执行观测，每条 10 个品种，共 100,000 笔成交。
- 价格、权益、目标权重、目标数量、金额换算和成交手续费均有明确合成证据；没有通过补零、补成交或填补未知字段制造完整度。
- 独立准备进程复用实际 `observation_fact_values()` 和 `source_fact_values()`，每 100 条提交一次结构化源事实。准备耗时 14.888 秒，**不计入刷新耗时或刷新内存**。
- 使用 SQLModel 当前表定义，安装 0012、0020、0034、0035 的真实触发器。此测量不覆盖 Alembic 升级和旧数据首次补齐耗时。
- 源事实冻结后，仅在这份临时库中将 `executerecord.raw_input/raw_result` 写成非法 JSON，再安装失效触发器。测量进程拒绝调用历史投影函数；三次刷新均成功，因此这些刷新没有重新解码遗留历史 JSON。

测量进程不导入完整 HTTP 应用，也不启动交易、调度或真实渠道连接。实际调用 `enqueue(force=True)` 和 `AnalysisManager.run_once()` 三次，使用真实原生二进制，不替换计算或发布实现。

## 本次结果

Python 完成分析模块导入、尚未打开测量数据库时的 RSS 为 **146.35 MiB**。首轮还包含首次准备日历及其他首次使用路径，因此应与后续轮次分开看。

| 同一进程连续刷新 | 第一轮 | 第二轮 | 第三轮 |
|---|---:|---:|---:|
| 入队至事务发布结束 | 2.380 秒 | 1.420 秒 | 2.176 秒 |
| Rust 计算、JSONL 接收校验及磁盘暂存 | 0.494 秒 | 0.480 秒 | 0.476 秒 |
| Python 原子发布与成本复制 | 0.820 秒 | 0.887 秒 | 1.652 秒 |
| Python 与 Rust 合计采样峰值 RSS | 201.46 MiB | 204.91 MiB | 205.55 MiB |
| Python 单独采样峰值 RSS | 184.93 MiB | 187.76 MiB | 190.52 MiB |
| Rust 子进程单独采样峰值 RSS | 17.52 MiB | 17.42 MiB | 17.42 MiB |
| 每轮 JSONL 磁盘暂存量 | 208,058 字节 | 208,058 字节 | 208,058 字节 |

第三轮开始实际清理不再保留的首版快照及其成本子表，发布耗时高于第二轮。时间拆分中的两个阶段不包含前面的账户读取、事实完整度检查和日历准备，所以不应相加后当成完整刷新耗时。

RSS 由外部控制进程每约 5 毫秒读取一次，合计同一时刻 Python 分析进程与递归子进程的 RSS；不是把各自不同时刻的峰值相加。它覆盖原生分配，但共享页可能重复计算，短暂尖峰可能未被采到。不是仅计算 Rust RSS，也不是 Python `tracemalloc`。

Python 刷新后 RSS 从第一轮的 184.92 MiB 上升到第三轮的 190.52 MiB。三轮不足以证明长期稳定或排除泄漏；不能据此宣称整个服务常驻只有约 18 MiB，或所有 Python 内存已经移除。

## 发布完整性与查询证据

每轮发布后使用逐行哈希检查全部规范化结果表与成本表，排除快照 ID 后的内容和顺序一致。三轮哈希均为：

```text
b80bd2d544dd70677b690e9c17507fba1f2549e76948fcc66c8d351b9fc3f073
```

每份当前快照包含 3 个区间、543 个曲线点、540 条逐日成本、540 条分币种日费用，以及 10,000 条执行成本、100,000 条成交成本。执行品种、成交事务和事务手续费子表各 100,000 条。三轮保留快照数为 **1 → 2 → 2**。快照 `ranges/settings` 保持空对象，实际结果来自类型化字段。

这里验证的是三次实际发布的完整度、重复一致性和版本保留；不是再次将这份大输入与旧 Python 全链路计算逐字段对照。小型业务场景的 Python 对照由结构化发布契约测试负责。

SQLAlchemy 查询捕获记录到三轮共 **21 次**成本 `INSERT ... SELECT`，即每轮 7 张表在 SQLite 内复制，没有将全部成本历史先取到 Python。

捕获也如实记录了 **6 次**引用遗留 JSON 列的缺失事实查询：每轮检查观测事实与成本源事实各一次。它们带 `NOT EXISTS` 条件，在已冻结完整的输入上返回零行。因此准确的结论是“没有读取到并解码历史 JSON”，不是“SQL 文本完全不再引用 JSON 列”。原始测量报告保留了这两种 SQL 的完整文本。

临时数据库文件从 99.09 MiB 增长到 278.01 MiB。结构化源事实与当前、上一版成本仍有存储复制；SQLite 删除后不会自动缩小文件。因此本次结果不能用来承诺磁盘占用不再随历史增长。

## 复现和限制

以下是历史运行命令，仅适用于保留旧发布入口及 `executerecord.raw_input/raw_result` 列的测量版本，不能在当前 checkout 复现。需使用对应版本已装开发依赖（包括 psutil）的 Python 环境和预先构建的 release 二进制：

```bash
PYTHONPATH=. python scripts/benchmark_structured_publication.py \
  --binary rust/analysis/target/release/axile-analysis \
  --output /tmp/structured-publication-measurement.json
```

准备进程与测量进程各有 20 秒硬超时；一次运行最多 40 秒左右。测量进程内每次 `run_once()` 也有 20 秒取消期限。原始报告包含字节值、每轮耗时、阶段耗时、表行数、重复输出哈希、查询文本和二进制校验和。临时库结束后自动清理，不读写真实数据库。

这是一次三轮合成测量，没有修改前后完整服务器的同机对照，没有冷缓存控制，也没有 P95 统计。尚未测量完整 API 进程与分析的合计占用、账户列表尾延迟、真实历史分布、并发源写入和 WAL 长期增长。需要用这些指标判断整体服务收益，不能由独立回放数据代替。
