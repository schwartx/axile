# 原始回放：首个端到端检查点

2026-11-15。基线 `349eecc68c3bd32f18d88d1acb364375af769951`，分支 `codex/replay-single-source`。

本文件保留首轮测量；当前业务观察、索引代次及资源验证进展见[业务检查点](raw-replay-business-checkpoint.md)。以下旧产物哈希和缓存容量不代表继续实现后的构建。

这是可运行的原始证据预览：录制 → 原始块/索引 → 只读接口 → Worker/WASM → 页面。支持录制段内按观察时间及 `capture_seq` 精确跳转，显示一条原始盘口观察和最近 32 条证据。它尚未提供完整的执行场景、订单/持仓推导和统计，不能作为提案整体完成或上线验收。

## 已接通的路径

- `ExecutionReplayWriter` 只接受 v2，写 `raw-<recording>.mcap`。MCAP message 使用 `axile.ndjson.zlib.v2` 编码；每个观察的业务载荷只在压缩原文中保存一次。复用已安装的纯 Rust zlib 实现，使浏览器能独立解码。
- `.replay-v2.sqlite` 只有录制/流目录、执行直接关系、观察位置、块位置/长度/校验和及提交水位。没有事实表、合并成交或投影检查点。提交凭据先随 MCAP 同步落盘，再发布索引。关闭 MCAP 元数据索引累积，writer 不保留全部提交目录。
- Python 采集端删除归属补全和历史成交跟踪，只保守保留直接关注品种、查询身份/代次及有界队列。开启市场流前记录原始 `/capture` 证据；溢出停止录制并报错，不阻塞等待 writer、不静默截断。
- 新接口位于 `POST /api/v1/account/executions/{id}/replay/raw/{session,manifest,plan,block,control}`。账户仍由执行业务真源确定；响应绑定账户、执行、录制、索引代次和已提交序号，页面检查归属。服务器不解压、重放或生成状态。
- 时间定位先把查询上界收紧至冻结序号对应的观察游标，防止扫描同时间戳的后来追加数据。物理块在每次计划中去重；缓存命中可跨已结算任务复用。
- `RawBlock` 在独立 WASM 中解压、解析原始观察。无关载荷用借用的 `RawValue` 跳过；每次至多消费 16 条观察，再让出 Worker 事件循环。主线程不累积历史或打包完整 JSON。现有账户分析 WASM 保持独立产物。
- 旧回放 GET/window 入口已移除，没有服务器计算兜底或旧格式兼容。当前数据包导出对 v2 明确报错，避免静默漏掉新录制。

## 拒绝、取消和结算

服务端在打开索引、解释数值 ID 之前检查会话、根序号、attempt、期限和额度。取消水位只前进；旧 attempt 的迟到读取会被拒绝，旧取消不能取消新 attempt。根任务 ACK 后回收详细记录，但保留连续根序号水位；旧根的数据请求不能重新注册。尚未到达的数据请求也可先 seal。

索引代次不符先报失效，不能按新字典解释旧 ID。一次请求只持有一个短索引事务。发送分为最多 64 KiB 的片段，实际发送停止后才归还并发额度；慢发送最多等待 2 秒。结算函数幂等，失败/取消已经读到的字节仍累计。

浏览器只保留一个运行任务和一个最新候选。取消会终止当前 Worker、取消网络读取，并在原根任务上 seal、取回回执和 ACK，完成后才开始下一个根。结算回复丢失时只重试控制请求。Worker 不回复时主线程 5 秒内终止它；不依赖 Worker 的 `finally`。租约每 30 秒低频续期，不延长根任务期限。

读取执行体持有跨进程独占锁。在途查询/响应通过强引用持有原执行体，尚未停止时新实例无法取得锁。取得锁以后再保守等待完整速率窗口（10 秒加 1 秒桶边界），才准入历史读取。旧 epoch 返回失效，当前没有自动恢复旧实例任务或重置其预算的路径；回执明细确已失去时明确失败，不冒充已精确结算。

## 当前固定上限

| 范围 | 上限 |
| --- | --- |
| 单观察 | 512 KiB、16,384 个 JSON 节点、深度 10；复制前检查 |
| 采集队列 / 原生待提交原文 | 8 MiB / 约 1 MiB 加一个合法事件 |
| 每录制流目录 | 128 项，超限明确故障 |
| 页面目录 / 单响应 | 最多 64 段录制 / 元数据 256 KiB |
| 压缩块 / 解码原文 | 600 KiB / 512 KiB + 换行 |
| Worker | 独立 WASM 硬上限 32 MiB；压缩缓存 4 MiB、最多 64 块 |
| 页面输出 | 32 条证据、盘口每侧最多 20 档；明确为预览 |
| 有限根任务 | 30 秒、8 MiB 读取/元数据响应、200,000 个 SQLite 指令计量单位 |
| 账户速率窗口 | 32 MiB、2,000,000 个索引指令单位；控制通道另限每约 2 秒 256 次 |
| 读取并发 | 全部账户 4、单账户 2、单根任务 1 |
| 状态记录 | 最多 64 个账户计量项、64 个会话，单账户 4 个会话；租约 90 秒 |

元数据按实际编码字节结算；原始逻辑读取和 SQLite 工作量分别累计。指令计量按 100 条指令回调并补一个尾部单位，作为保守工作量，不等同 CPU 时间。预算不因更换根任务或会话清零；长期播放没有会话终身字节上限。控制请求有独立计数/速率，不挤占清理所需的数据额度。

这些限制约束当前回放工作集，不是浏览器 RSS 的硬保证。主线程、网络、传输峰值、Worker JS 与 WASM 容量应分别看待。超限保护也不等同于完整业务任意跳转验收通过。

## 真实规模证据

大阪一段已关闭录制的 13 个不可变分片，共 667,513,254 字节。仅离线取出其中的原始观察作为测试输入，忽略旧投影和检查点；未运行旧引擎对照，也未修改线上文件、服务或交易。样本中的观察已经过当时的规范化处理，不能据此验证所有新采集语义。

- 4,820,994 条观察、最大观察 2,356 字节，提取后的原文合计 6,881,381,912 字节。
- 新 MCAP 766,495,710 字节，168,840 个块，压缩载荷 727,703,979 字节；索引 425,381,888 字节。这是该段样本的绝对体量，不是全库节省百分比。
- 优化构建录入耗时 236.99 秒，录入工具峰值 RSS 128,188,416 字节，包含 Python 样本读取及 zstd 解码，不能当作线上常驻 writer 的独立 CPU/内存结果。
- 目标在输入提取时固定：每 20,000 条观察一个精确游标，加末尾，共 242 个；每个目标各自形成并结算一个根任务。每批 60 个后等待 6 秒，主动遵守账户读取窗口。
- 浏览器逐一检查目标的最后盘口原始序号和最近证据序号。固定目标所需的不同块共 2,961 个，`D = 14,636,623` 字节。整段 `R_total = 14,636,623` 字节，`R_total/D = 1.0`。没有把完整录制大小充当分母。

| --- | ---: |
| 60 | 3,566,668 |
| 120 | 7,501,414 |
| 180 | 10,957,971 |

同源静态验证产物使用实际回放组件、Worker 和独立 WASM，API 使用生产路由实现；执行归属查询由隔离映射代替。浏览器本机验证不代表公网延迟、全新浏览器 WASM 冷启动或完整应用导航验收。WASM 容量峰值 1,310,720 字节，压缩缓存峰值 423,773 字节；额外增长 32 MiB 的请求被模块硬上限拒绝。主线程堆、API CPU/峰值 RSS、实际元数据和控制次数记录在原始测量文件中，不能以系统缓存命中宣称零磁盘成本。

该次静态产物测量的逐目标耗时中位数 128.15 ms、最大 206.6 ms；主线程堆从 29,771,206 到 32,796,745 字节，包含基准记录。API 进程 CPU 累计 12.13 秒，峰值 RSS 在测量前后均为 148,766,720 字节；数据响应 15,833,688 字节，其中原始块 14,636,623 字节，另有 730 次控制请求。HTTP 头和控制响应的实际网络字节未计入数据响应值；控制响应另受固定结构和独立速率约束。系统报告的块读计数为零只说明此次读取命中了缓存。

另测末尾冷跳转、回跳、缓存命中、40 个快速候选只交付最终目标。注入不回复的真实 Worker，约 5 秒后终止，下一次精确跳转成功；失败尝试和恢复合计读取 54,178 字节，结束后服务端活动读取为零。

同账户、同一 SQLite 索引并行追加 50,000 条压力观察，生产者耗时 14.18 秒、CPU 3.80 秒、峰值 RSS 122,503,168 字节；同时完成的 60 个历史目标全部精确，最大耗时 133 ms，读取 3,693,907 字节，WASM 容量仍为 1,310,720 字节。这是离线压力生产者，不是实盘交易验收。另抽查 12 个分散目标，解码后每侧前 20 档价格/数量与对应原始观察相同。

## 继续实现的边界

当前页面按录制段预览原始观察，未按执行生命周期生成完整场景。稳定/弱成交归约、订单及持仓求值、证明成员查询、依赖修订、批量读取、多目标播放组、索引重建恢复、完整采集覆盖与故障证据、导入导出/保留清理尚未交付。需要这些输入的统计没有展示为精确结果。

因此，本轮证明的是这个最小读取范围内的有界工作集、精确游标和跨根累计成本；不能外推为全部业务状态、所有合法大事件组合、证明密集或缓存反复淘汰场景均已通过提案验收。还未完成生产采集/交易并发验收、全仓门禁或上线。仓库既有 v1 服务测试仍引用已删除入口，需随新语义用例到位而退役或改写；本检查点没有为了通过它们恢复旧协议。
