# 当前委托

账户详情的“持仓 vs 目标”卡片在手动模式提供「查看在途委托」入口，自动模式显示「在途委托 · N」数量摘要。点击后打开账户级弹窗，查询该账户在交易渠道中仍未结束的订单，包括不能关联到 Axile execution 的订单。执行结束或暂停自动执行后，这个入口仍然可用。

弹窗展示合约、买卖与开平、委托价、委托量、已成交量和状态。展开某笔订单可查看订单编号、下单时间、剩余量、已知原生订单身份及关联 execution。未知字段保留为未知，不从净持仓推断开平或订单终态。

## 查询与撤单

- 默认「手动拉取」：进入账户页不查询，点击「查看在途委托」或「刷新」才读取。手动模式不随页面恢复读取自动查询。
- 可切换为「自动拉取」，账户页每 15 秒读取并显示在途数量，账户委托弹窗或品种详情打开期间每 3 秒读取。两处入口共用拉取方式，按账户保存在当前浏览器，其他账户默认仍为手动。数量未知、数据不完整或最近读取失败时，摘要显示「待确认」。
- 尚未读取时显示「尚未拉取委托」，不推断为零挂单。无挂单且查询完整时显示明确空态；失败时显示待确认，保留页面最后一次成功数据，失败不能作为零挂单证明。
- 撤单前重新查询渠道，核对合约和完整订单身份。只撤这笔订单的未成交部分，不影响已成交持仓。
- 请求受理后核对一次并显示“撤单确认中”，直到渠道回报或后续查询证明订单已撤、已成或其他终态。手动模式需点击刷新继续核对，自动模式随定时读取更新。订单从挂单列表消失不单独作为撤单成功证明。
- 部分成交后撤单仍保留实际已成交量。柜台拒绝撤单时显示实际拒绝结果。
- 查询/撤单与长时间调仓使用独立 worker 通路。人工操作复用执行器公开接口及风控计数，运行中共用该执行的 guard，空闲时使用独立控制审计上下文。
- 算法仍在运行时可能继续提交新委托。暂停自动执行只停止后续计划；需要停止当前算法时，使用账户现有的终止执行操作。

## 账户连接

所有渠道（包括 Binance）统一使用每账户独立的常驻 worker。调仓、清仓、资产查询和当前委托共用账户连接；执行结束或暂停自动执行不会关闭连接。修改连接配置、删除账户和服务退出时回收 worker。

首次查询可以建立连接。已发生连接故障时，页面读取不会反复登录；自动执行准备遵守 30 秒冷却，显式重新连接可以绕过冷却，同时到达的重连请求共用一次尝试。恢复后先核对资产和未完成委托，再标记连接就绪，不重放之前的交易请求。

首次资产或委托查询留出 60 秒连接准备和 30 秒查询预算；就绪后的查询预算为 30 秒。空闲 worker 请求超时后回收，主进程继续保留恢复冷却，页面轮询不能通过创建新 worker 绕过限制。委托通路超时时，有排队或正在执行的交易任务则保留 worker，并将本次结果标为待确认。

账户连通状态可打开连接详情，执行「重新连接」或「断开连接」。对应接口为 `POST /api/v1/account/{account_id}/connection/reconnect` 和 `POST /api/v1/account/{account_id}/connection/disconnect`，返回更新后的连接详情。账户有排队或正在执行的任务时返回 HTTP 409。连接操作不修改自动执行配置，也不触发调仓或清仓；主动断开后，读取和计划执行都不会自动恢复连接，需要显式重新连接。

当前会话只使用本次服务进程的存活实例和监控快照，状态为 `uninitialized`（未建立）、`connecting`（正在准备）、`ready`（会话就绪）、`recovering`（正在恢复）、`unavailable`（暂不可用）、`disconnected`（已断开）、`unknown`（待确认）。SDK 初始化成功或单次请求成功不直接构成会话就绪证明；资产与未完成委托核对完成后才会就绪。监控只读取 worker 本地快照，过期时显示待确认，不触发柜台探测或重登。

账户列表、详情页和连接弹窗共用连接实时状态。`GET /api/v1/events/stream` 在订阅及重连时发送 `connection.snapshot` 全量快照，随后通过 `connection.update` 推送变化；载荷包含 `stream_id`、递增 `version`、`kind`、`data: [{account_id, connection}]` 与可选的 `removed`。`connection` 包含当前状态和连接历史详情。前端不轮询连接状态，也不使用账户 REST 响应覆盖实时状态；事件流断开或连接域报错时标记待确认，收到新快照后恢复。打开弹窗只展示共享状态，不触发连接查询或登录。

状态标识保留“交易前置失败”“认证失败”等具体文案；链条图标用于连接操作按钮，断链图标用于断开连接按钮。点击标识打开连接详情，旁边的“连接账户／重新连接”是独立操作。打开暂停账户不会登录：资产、委托等查询只复用已就绪会话，后端同样禁止首次查询建立连接。未连接时显示已有快照及更新时间，委托标为“连接后获取”；连接成功后刷新资产并恢复允许的委托获取方式。再次断线即停止依赖连接的查询，等待显式重连；连接不会解除暂停或触发交易。

API 的 `observed_at` 是当前状态更新时间，`sampled_at` 是本地监控采样时间；`last_success_at` 是最近一次实际账户访问成功时间，`last_failure_at` 与详情中的 `last_failure` 保存最近失败证据。历史成功不代表当前在线，恢复成功也不会删除历史故障。页面将历史失败单独标注，连接详情打开期间每 5 秒只读刷新当前状态。

服务重启会撤销旧实例的写回权限，当前会话回到未建立；worker 退出、通信失败或请求超时会结束当前会话，迟到的成功响应不能恢复旧会话。主动断开意愿跨重启保留，只有显式重连或连接配置变化才解除。迁移 `0028` 添加历史与断开意愿字段；旧成功观察无法区分初始化与实际访问，因此不回填访问成功时间。

## REST 接口

`GET /api/v1/account/{account_id}/orders` 返回 `data`、`count`、`sampled_at`、`complete` 和最近人工撤单回执 `cancellations`。`refresh=true` 强制向渠道读取；普通查询使用最长 4 秒缓存。手动查看、刷新及撤单后核对使用强制读取；自动模式的定时读取可复用缓存。

`count=null` 和 `complete=false` 表示有订单终态尚未确认，此时可能包含标记 `uncertain=true` 的最后已知订单。原生身份只输出白名单，不输出账户凭据或原始渠道载荷。

`POST /api/v1/account/{account_id}/orders/cancel` 请求：

```json
{"request_id":"调用方生成的唯一标识","symbol":"rb2610","order_id":"完整原生订单标识"}
```

HTTP 202 表示请求已处理，实际结果查看回执 `state`：`submitted`、`unknown`、`failed` 或 `terminal`；`submitted` 不等于撤单成功。传输超时不自动重发撤单。相同请求标识重放、同一订单尚未确认的重复请求复用已有回执。明确失败后可人工发起新请求。

同一账户、同一合约和订单号的渠道明确终态会收敛本地撤单状态，即使回执来自另一个客户端的请求号，或原请求时间早于本地请求。页面会记住本页操作过的订单的已确认结果，后续最近回执列表不再包含它、响应迟到或查询失败都不会将终态降回待确认。一次撤单失败仍按请求区分，其他请求的失败不作为本次撤单或订单结束的证明；实际已成交量与最终状态以渠道回执为准。

幂等回执保存在当前服务进程，服务重启后应先重新查询订单，再决定是否操作。所有联机行为通过已配置的交易渠道；下面的回归不连接真实柜台。

## 从持仓行查看品种详情

账户详情的「持仓 vs 目标」保持四列和五行滚动预览。点击一行或聚焦品种按钮后按 Enter，可打开该品种的「持仓与目标」弹窗；键盘打开时关闭后焦点返回品种入口；鼠标打开后按 Escape、点关闭或点遮罩均不自动聚焦品种。除了已有持仓，表格会追加尚未持仓的非零目标品种。

弹窗展示：

- 当前多头、空头持仓及可用量、今仓和昨仓；缺失分项标为未记录，不通过净仓或可用量倒推。
- 目标持仓、当前数量差、在途委托全部成交后的预计持仓及预计剩余差额。
- 保存的策略权重、账户权重、账户乘数、权重精度、计算时权益、参考价格、合约乘数、数量步长与最小交易限制，以及实际数量换算过程。直接数量目标不套用权重公式；有币种换算时同时说明汇率。
- 该品种的未完成委托、订单展开详情和单笔撤单结果，复用账户当前委托的查询及撤单状态。

目标权重时间与数量换算记录时间分别显示。旧记录没有换算依据、等待下一次执行换算或换算失败时，保留已知目标权重并说明原因，不采用当前行情推算历史目标数量。已计算目标中未包含的现有持仓，其目标为空仓。

预计持仓只计入未成交的剩余数量；撤单请求受理后，仍待实际终态确认。由于持仓快照和当前委托来自独立采样，只有观测时间一致、数据完整且订单状态已确认时才给出确定的预计数量。采样不同步、查询失败、未知开平或撤单结果待确认时，预计数量显示「待确认」并说明原因。

手动模式打开品种详情不会查询委托，点击区域内「查看在途委托」后才读取；自动模式在弹窗打开时开始读取。「刷新持仓快照与委托」显式刷新保存的资产/目标快照与当前委托，不会重算目标、触发执行或下单。数量差额仅用于说明，不代替执行器的可用数量、风控和交易规则检查。

品种详情使用横版两列布局：顶部为当前、目标及待调数量，左侧为换算公式，右侧为当前持仓和在途委托。计算参数默认折叠，未知原因通过可聚焦的提示图标查看；账户名称不在弹窗中重复展示。确定为零的持仓方向省略，多空同时存在时保留两行。没有该品种在途委托时不展示预计持仓与预计差额。窄屏自动改为单列。
