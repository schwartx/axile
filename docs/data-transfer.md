# 账户数据传送

两端安装匹配的 Axile（使用私有渠道时也需安装匹配插件）。在「高级设置 → 存储」点击「打开数据传送」，在弹窗中操作；规则独立保存，无需重启。接收端使用现有账户、绩效、执行和回放页面；无需单独分析界面。

数据包选择、ZIP 打包解包、路径与大小校验、数据库和录制落盘、回执校验、来源端批次恢复及清理由 Rust 统一执行。Python 保留应用配置、HTTP 拉取、接收确认补交和定时调度；跨原生边界传文件路径，不传整包内容。

## 联网拉取

A 是接收端，B 是来源端。A 主动请求 B 返回数据包，B 不主动连接 A。接口不要求授权，能访问 B 的人即可下载其数据包。

1. 在 A 填写 B 的「来源端地址」（含协议、端口）。地址应通过 HTTPS 或受信任的加密隧道访问；数据包包含账户凭据和自定义代码。
2. 默认拉取至最新，也可以切换到「指定范围」，按北京时间选择日期和时刻。执行记录使用半开区间；资产快照及关联事实保留完整上下文，录制按北京时间的边界日包含已封口段和共享片段。
3. 在 A 开启「自动拉取」并设置间隔，以及 B 的执行记录、回放保留天数。默认关闭自动拉取；保留天数为空时显示「不清理」。保存规则后重启 A 仍会恢复定时任务。
4. 在 A 点击「立即拉取」。B 返回一致性数据包，A 校验并导入后交回回执，B 验证回执再清理；B 不需要配置联网地址或调度。
5. 下载失败时 B 保留待取批次供重试。导入失败不交回回执；A 导入后保存未交付的回执，重启或下一次拉取先补交该回执，沿用原来源和保留规则。确认回复丢失时可重复交回，不重复下载或扩大清理范围。

## 离线传送

在弹窗展开「离线传送」。发送端导出 `.axile` 包，接收端上传。接收成功会下载 `receipt.json`。将此文件交回发送端的「交回离线接收确认」，才会按交回确认时填写的源端保留规则清理。导出成功本身不允许删除源数据。

## 数据与安全边界

- 第一版采用一个来源对应一个接收库。首次接收要求本机账户和组合为空；后续仅接收同一来源。不合并独立实盘实例的 ID 空间；有冲突则整体拒绝。
- 数据库通过 SQLite 一致性快照生成；由 Rust 执行导出、累积导入和清理。匹配的表结构、文件大小、哈希和相对路径均需验证，单包展开预算为 4 GiB。
- 账户配置与凭据、组合、业务事实、录制及索引、自定义算法目录随包保存。连接状态、运行态对齐、通知投递状态和分析缓存不恢复；接收后账户调度暂停。自定义算法在接收端重启后加载。
- 来源端清理不传播到接收端。接收端保留已累积的历史；同一来源再次传送会去重并更新其现有记录。
- 接收端记录每次导入行的主键和内容摘要。独立新增的冲突行或在接收端修改过的导入行会使本次接收整体失败，不覆盖本机改动；不同主键之间的唯一键冲突同样拒绝。
- 源端仍活跃的流控会话在接收端标为未完整的历史，保留未知的结束时间；后续传送可更新为源端的最终状态，接收端重启不会改写这些会话。
- 发送端只有得到与本机包清单匹配的接收确认，才能清理已传送且早于保留期限的记录。保留每张使用普通 ROWID 表的最高 ID 行，避免删除尾部后新记录复用 ID；资产快照、仍有审计引用的冻结输入等上下文暂时保留。
- 回放按整份录制回收：任何正在写入的段、未传完整的文件、索引仍标记活跃或存在跨录制引用的会话都保留。活跃长会话可能超过保留天数，保留规则不能视为硬磁盘配额。
- 校验、数据库导入或文件落盘任一步失败，不签发接收确认，源端不因本次传送删除数据。重试导入可以补齐尚未落盘的文件。
- 传送目录为私有文件。已确认包会释放本地暂存；离线待确认包会占用磁盘，需要及时交回确认。

测试均使用任务隔离数据库；不需要连接交易账户。
