# 执行证据导出

后端以 ZIP 导出持久化事实、可读摘要和脱敏清单。导出只读数据库及可选日志，不调用交易执行器，不刷新柜台持仓，不修改账户或业务审计。

## 管理界面

执行详情右上角的「导出本次证据」按 execution_id 导出；排队中、运行中及失败的执行均可导出。账户「执行记录」页的「按日期导出」使用北京时间自然日，包含首尾日期，最多 31 天。默认沿用列表日期，超过上限时要求调整，不自动缩短；页面的品种和状态筛选不影响证据范围。

从绩效快照进入时，能确定的日期会带入弹窗；只知道快照整体范围或记录编号时，需要自行选择日期。证据来自当前服务器留存材料，可能与绩效快照不同。

两处入口共用导出弹窗，默认「分享副本」、不包含日志。选择「内部诊断」会展开其保留内容说明；关联运行日志可以单独勾选。生成期间锁定配置，失败保留设置并支持查看错误详情和重试。取消、关闭弹窗或切换账户/执行会中止浏览器请求并抑制迟到响应的下载，不保证服务器立即停止生成。

完成提示「已发起下载」表示文件已交给浏览器，不表示已保存到磁盘。文件名使用日期或执行编号，不带账户名称；内部副本带 internal 后缀。

## 接口

基础路径 `/api/v1`。

```http
GET /account/executions/{execution_id}/evidence
GET /account/{account_id}/evidence?start_date=2026-10-15&end_date=2026-10-15
```

共同参数：`profile=shareable|internal`，默认 `shareable`；`include_logs=true|false`，默认 `false`。两种模式均排除凭据及代码原文。客户端不能指定日志文件路径。

日期接口必填 `start_date`、`end_date`，包含首尾日期，最长 31 天。`timezone` 是自然日的 IANA 时区，默认 `Asia/Shanghai`。`legacy_timezone` 是无时区历史时间的解释时区，省略时采用服务器本地时区；此解释始终记录为假设。

成功响应为 `application/zip`，带附件下载文件名和 `Cache-Control: no-store`。未找到执行或账户返回 404；材料归属冲突返回 409；无效参数返回 422；超规模返回 413；生成超时返回 408。业务错误包含 `detail.code`、`detail.message`。

本地调用例子：

```bash
curl --fail --output execution-evidence.zip \
  'http://localhost:8000/api/v1/account/executions/EXECUTION_ID/evidence'
curl --fail --output account-evidence.zip \
  'http://localhost:8000/api/v1/account/1/evidence?start_date=2026-10-15&end_date=2026-10-15&timezone=Asia%2FShanghai&legacy_timezone=Asia%2FShanghai'
```

## 选择和数据结构

自然日转换为 UTC 半开区间 `[start_inclusive, end_exclusive)`。按与窗口重叠的执行意图、期间的结果和执行事件、控制事件、流控会话联合发现执行，包含排队中、运行中、失败和终止的执行。审计事件缺失时，仍可由计数桶发现上下文；桶不含逐笔操作时间，选入原因明确标为时间假设。

按 execution_id 去重后读取整次执行上下文，因此跨日执行可以出现在两天的包中。`control-summary.csv` 只汇总窗口内的控制事件，事件原有 `control_date` 原样保留。无 execution_id 的旧结果使用 `legacy-record-{record_id}` 建包内索引，真实 execution_id 仍为 null。

```text
manifest.json
summary.md
executions.csv
control-summary.csv
logs.jsonl                       # 请求日志时
executions/<安全目录标识>/
    intent.json
    record.json
    events.jsonl
    artifacts.json
    control-events.jsonl
    counter-deltas.jsonl
    control-sessions.json
    orders.csv
    trades.csv
    reconciliation.csv
    summary.md
```

JSON/JSONL 是选定脱敏模式下的持久化事实；CSV 和 Markdown 是派生视图，附来源定位。任意历史标识不会直接作为不受约束的归档路径。

`manifest.json` 协议版本为 1，包含 export_id、导出器版本、快照时间、日期选择规则、来源行数、每次执行的状态和缺失材料、日志采集状态、脱敏规则版本及文件清单。文件清单含路径、字节数、SHA-256、来源和可用行数；校验针对导出后的字节，清单不计算自身校验值。

## 结果含义

`database.read_complete` 只证明单个显式数据库读事务中的材料已全部读取。`executions[].coverage` 分别给出缺失附件和问题：provisional 是阶段快照，incomplete 是发现缺口，available 仅表示检查所需材料具备。审计写入为尽力而为，available 不保证所有柜台回报均已保存。

任务状态 task_status、执行器状态 output_status、业务结论 business_outcome 分别记录。任务成功不证明成交或到位。逐合约持仓核对只消费现有持久化 reconciliation；缺失时保留未知。活跃订单只限本次执行已观察订单，不代表导出时账户全部挂单。

控制汇总按 control_date、操作、决策、结果及 counted 分组；放行不等于柜台接受，报单不等于成交。外层 cancel_order 与原生 cancel_order_ctp 独立列示，分钟、日和合约计数增量不重复相加。

新执行在 worker 和线程后端真实执行前冻结 environment_snapshot，记录 Axile/执行器所属分发包版本、Python 版本、算法标识和执行器实现摘要。历史没有快照时为未知，导出器当前版本不替代历史版本。

## 脱敏与日志

shareable 将账户替换为一致别名，移除登录身份、地址、本机路径、任意代码和自由文本异常；未知插件字段按白名单排除。仍保留真实交易数量、价格、时间和原生订单/成交编号，适用于交易核对，不是匿名交易数据集。

internal 保留账户名称及更多诊断字段，递归排除密码、密钥、token、认证字段、账户连接配置、webhook 和代码。文本另清洗已知凭据赋值形式、认证头、URL、绝对路径。内部材料含自由文本，按内部诊断材料处理。

脱敏规则版本为 1；内部清单列字段路径和处理规则，不记录被移除值；分享版只列规则计数，避免动态路径泄露。原数据库材料不被改写。

日志仅扫描服务配置目录内 axile*.jsonl，按完整 execution_id 关联，并核对提供的账户归属。分享版仅保留结构化上下文，移除消息和异常。日志在数据库快照后独立采集，清单记录采集时刻、扫描量和读取、格式、截断问题。日志存在不证明保留周期完整。

## 资源和失败处理

默认单包最多 100 次执行、采集扫描最多 100,000 行、采集与归档累计字节预算 64 MiB、生成预算 60 秒。日志最多扫描 32 个文件、64 MiB。边界集中在 EvidenceLimits，超限整次失败并要求缩小范围，不返回静默截断的 ZIP。

数据库读取结束即释放读事务，压缩在线程进行。打包失败、生成取消、下载完成及发送失败会释放临时文件；只返回已完成的归档。可选日志局部不可用时保留业务证据并明确日志缺口；核心读取失败不会返回空包冒充成功。
