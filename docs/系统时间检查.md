# 系统时间检查

顶栏主题切换左侧的时钟图标打开检查弹窗。检查对象为 Axile 服务所在机器，浏览器只展示结果。功能不会修改机器时间，也不影响账户连接、下单或撤单。

## 时间源与检查

默认使用阿里云 `ntp.aliyun.com`，也可以选择腾讯云 `ntp.tencent.com`、清华 TUNA `ntp.tuna.tsinghua.edu.cn`，或填写自定义域名/IP 与 UDP 端口。默认端口为 123，允许偏差为 500ms。

弹窗采用横版单页布局：左侧展示时间偏差及检查详情，右侧直接编辑来源、阈值和自动排程；窄屏时上下排列。打开弹窗或编辑配置不会发起检查。底部「立即检查」执行一次；配置有修改时显示「取消修改」和「保存」，保存前暂不可检查。保存后仍停留在当前弹窗，不自动发起检查。选中源不可用时直接报告原因，不隐式更换来源。

检查直接查询选定的 NTP 参考源，不读取操作系统自动校时服务状态。NTP 采用四时间戳估算偏差，最多采样三次，选择往返延迟最低的有效样本。公网路径不对称可能影响估算，毫秒显示不代表同等测量精度。

## 自动检查与顶栏状态

自动检查默认关闭。开启后复用通用定时编辑器，可选择快捷、高级或自定义 Cron 排程；调度使用北京时间，界面仅显示下次检查时间。保存立即生效，关闭浏览器后任务继续，服务重启后恢复排程，不补跑停机期间的检查。

- 蓝色时钟：自动检查开启且没有告警。
- 琥珀色时钟及告警标记：偏差超限或检查失败。
- 中性色时钟：自动检查关闭且没有告警。

告警优先于开关。关闭自动检查不会清除告警，下一次检查确认正常才恢复。参考源失败不会清除以前尚未恢复的偏差超限，弹窗会标明各项证据的时间。改变阈值或来源后也需要重新检查。

仅全新安装通过初始化向导完成配置后自动检查一次，失败不在下次启动重试；已有安装升级不触发首次检查。手工生成配置的部署可设置 `time_check_first_run = true`，领取记录保存在数据库，后续不会重复执行。

## 数据与接口

配置和最近检查证据保存在独立的 `time_check_settings`、`time_check_state` 表；不累积无限检查历史。日志记录检查摘要、异常和恢复；重复同类告警限频，不发送飞书通知。

接口位于 `/api/v1/system/time-check`：读取状态用 GET，保存设置用 PUT `/settings`，手动检查用 POST `/run`，排程预览用 POST `/schedule-preview`。设置带版本号，过期版本返回 409；非法配置返回 422。手动触发返回 202，检查由后台继续，同一时刻仅运行一轮。

前端状态通过已有 `/api/v1/events/stream` 的 `time_check.snapshot`、`time_check.update` 事件同步，不额外建立连接。读取接口或订阅事件不会触发检查。
