# CTP/TQ 共享合约目录

主服务持有一份内存目录，CTP/TQ worker 共用。目录不落磁盘、不设版本号；全量刷新成功后，整体替换当前目录。

## 查询与刷新

- 账户启动、连接恢复、worker 重建不加载全量。服务重启后目录为空，执行仅查询所需合约。
- 盘前北京时间 08:30、20:30 触发后台全量。启动处于该盘前窗口，且距实际开盘至少三分钟时，补一次预热。交易日历休市、不可用或午间休息时不启动预热。
- 自动触发按场次合并，成功后不重复；显式刷新不受场次去重限制。
- CTP 全量只发送一次不带合约过滤的 `ReqQryInstrument`，直接保存返回的乘数、价格步长等原生资料。天勤沿用 `query_quotes(ins_class=..., expired=False)`，分别读取期货、期权、组合的代码，不查询全市场合约详情。天勤实际使用合约的乘数、价格步长和持仓估值沿用 `get_quote` 对象。
- 只复用非暂停账户的已登录会话：优先 CTP，同渠道优先最近执行的账户；失败后按相同顺序切换。服务重启时读取最新执行记录的时间，暂停账户立即退出来源列表，保留已缓存目录。CTP 沿用同会话查询互斥锁，并限制取得查询权的等待时间。已经发出的查询不能在原生 API 中抢占，按需任务有自己的短等待上限，并可切换其他来源。
- 按需缺失列表交给渠道：天勤通过 `query_quotes` 查找代码，CTP 按原生 API 逐个指定合约；重叠请求共享在途查询。若共享记录仅有代码，CTP 向 CTP 来源按需补齐规格，天勤继续使用自身行情对象。
- CTP 查询仍经过既有账户控制。preset 的 1.5 秒是请求发送间隔，不是全量响应时间；不因盘前刷新而绕过渠道控制。

CTP 按需补齐不设固定整组超时，逐合约发送由既有流控控制。每次请求发送后按账户 `query_timeout`（默认 15 秒）检查连续无回调超时；等待查询锁和流控不计入响应超时，执行等待仍可取消。天勤按需整轮预算仍为 15 秒，单来源最多 5 秒。全量单来源默认 60 秒、整轮 180 秒，可用 `AXILE_CATALOG_SOURCE_TIMEOUT`、`AXILE_CATALOG_REFRESH_TIMEOUT` 调整。

## 发布与执行

目录允许只有交易所、规范合约代码和类型。CTP 记录还保留乘数、最小价位、到期信息及期权、组合静态字段；缺少这些字段的天勤代码目录仍有效。实时行情、交易状态、手续费、保证金率和账户权限仍由渠道维护。

查询失败、空结果或 CTP 规格无效时，保留现有目录。全量成功时不合并刷新期间的按需写入；新目录未包含的条目会被移除，后续执行重新按需查询。暂停交易不作为下市，日期型到期信息不会在到期日零点被提前判为失效。

调仓和清仓在下单前补齐目标、持仓、相关订单和合约依赖，再复制一份一致的所需资料供本次执行使用。后台刷新不会替换这份执行副本。

等待期间支持取消和超时，必要资料不齐全时不发送订单。取消一个等待者不会取消共享查询；晚到结果不会自动补执行。合约资料与初始化进度复用同一目录管道，独立于账户业务管道，来源退出后按截止时间接替；晚到 RPC 响应按请求 ID 丢弃。

连接验证卡片使用独立的螺纹钢样本查询，始终真实请求柜台，不使用公共目录代替诊断。

## 后台 API

以下接口沿用服务 API 的鉴权，不增加管理页面。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/instrument-catalog` | 目录记录数、来源数、最后成功时间、当前任务及最近错误 |
| `POST /api/v1/instrument-catalog/refresh` | 返回 HTTP 202 和刷新任务；全量在途时复用任务 ID |
| `GET /api/v1/instrument-catalog/refresh/{task_id}` | 任务状态、来源尝试、结果条数和失败原因；未知任务返回 404 |

任务状态为 `running`、`succeeded`、`failed`；内部自动触发还可能返回 `skipped`。只保留最近 100 项已完成任务，服务重启后不可查询旧任务。来源标识为内存会话 ID，不包含柜台地址或凭据。

执行审计增加 `instruments_waiting`、`instruments_ready`、`instruments_failed` 事件，包含相关合约、耗时及原因码，通过既有事件接口和 SSE 可观察。SQLite 的事件枚举以无 CHECK 约束的字符串保存，新事件不要求增加目录表或修改已存事件。

## 验证

在 Axile 仓库分组运行相关短测试，每条验证命令设置 20 秒硬超时：

```bash
uv run pytest tests/unit/executor/test_instrument_catalog.py tests/unit/executor/ctp/test_instrument_catalog.py
uv run pytest tests/unit/executor/tq/test_runtime.py tests/unit/executor/tq/test_executor.py
uv run pytest tests/integration/server/test_instrument_catalog_ipc.py tests/unit/server/test_instrument_catalog.py
```

Linux 仿真查询验收通过环境变量显式启用，测试会拦截下单、撤单与行权请求：

```bash
AXILE_CTP_CATALOG_LIVE=1 \
AXILE_CTP_CATALOG_CONFIG=/path/to/private-ctp-config.json \
uv run pytest tests/live/test_ctp_instrument_catalog.py -s
```

配置文件使用 `CTPAccountConfig` 字段，并限制读取权限；不提交凭据文件。另设 `AXILE_CTP_CATALOG_FULL=1` 可验证完整全量刷新及一次原生查询的请求数。
