# 执行算法

组合函数返回原始目标权重，执行层将它换算为可执行数量。下单算法负责处理目标持仓与当前持仓之间的差量，主交易和清仓可以分别配置算法。

## 当前公共算法目录

![天勤账户可选的公共下单算法](../assets/screenshots/08-reference/04-public-algorithms.png)

| 算法 | 用途 | 需要理解的边界 |
| --- | --- | --- |
| TARGET-POS-TASK | 期货目标持仓，适用于 CTP 与天勤 | 开平仓顺序、报价、等待与追单 |
| SINGLE-MAKER | 单边挂单，可按条件撤单追价 | 主动报价仍可能留下剩量 |
| TWAP | 按时间安排拆单 | 前片欠量滚入后片，计划时长不是严格截止时间 |
| POV | 按收到的增量成交量与参与率跟单 | 无量等待；到期补单可能不再受参与率约束 |
| CTP_OPTION_EXERCISE | CTP 期权行权、放弃或自对冲指令 | 独立指令用途，不用于账户主交易或清仓槽位 |

期货平仓顺序在账户级[平仓规则](/guide/daily#配置期货平仓规则)中设置，常规调仓和清仓共用。

下拉框只列出适用于当前渠道、主交易或清仓槽位的算法。其他算法仍可能存在于代码库中。

## 同一账户按时段选择算法

执行算法页顶部“通用”一行设置平仓规则、执行超时和回放录制。下方选择“默认”或具体品种，再编辑默认调仓算法和时段。清仓算法只在“默认”视图中提供配置入口，仍由全部品种共用。
点击“添加时段”后，在右侧顶部选择开始、结束时间，再设置算法和参数。切换配置保留草稿，底部统一保存或取消；时段列表和参数区分别滚动。

- 时段按北京时间每天重复，开始时刻包含、结束时刻不包含。例如 `09:30–10:00` 在 `10:00` 已不生效。
- 结束早于开始表示跨午夜，界面标为“次日”，例如 `21:00–次日 02:30`。时段不能重叠，首尾相接允许。
- 未命中时段时使用默认算法的配置。相同算法也可以在不同时段使用不同参数。
- 手动调仓、定时调仓和补发共用这套选择规则。每次在开跑前选定一次完整配置，执行期间跨过时段边界也不会切换。
- 修改配置影响后续执行。排队中的任务在开跑前选择算法，一键清仓继续使用独立的清仓算法。
- 时段只决定使用什么算法；交易日历、渠道限制和账户控制仍然生效。执行详情保留本次实际算法、参数和命中时段。

API 保留 `algorithm` 作为默认配置，`algorithm_schedule` 为时段列表，空列表表示全天使用默认配置。例如：

```json
{
  "algorithm_schedule": [
    {"start": "09:30", "end": "10:00", "algorithm": {"method": "TWAP", "params": {"total_duration": 120, "slices": 4}}}
  ]
}
```

此配置只是格式示例，实际参数仍需符合算法和渠道约束。

## 每个品种使用独立时段

直接选择“默认”或具体品种。切换条末尾的“＋ 添加品种”点击后在原位置横向展开输入框，保持行高和下方编辑区位置不变；按渠道显示示例并自动校验；格式说明和错误仅在输入框上方的气泡提示，校验失败或重复时不能添加；Enter 确认，Esc 取消，成功添加后自动收拢并选中新品种。添加时复制当前账户默认算法及时段，之后独立维护；选中品种后，可通过品种切换行最右侧的“删除品种配置”，确认后移除独立配置，后续沿用账户默认。页面底部统一保存或取消全部更改，未添加的输入不计入改动。

- CTP、天勤只需输入期货品种，如 `ag`、`TA`，界面也只显示品种代码。交易所由本地品种表自动识别，内部保存为交易所限定代码；同一品种的各月份期货合约共用配置，期权与组合不匹配。
- 掘金的股票和 ETF 需使用带交易所的完整证券代码，如 `600000.SH` 或 `SHSE.600000`，两种写法指向同一证券。这里只校验格式，不核验证券与交易所的归属关系；格式合法但交易所填错时，会匹配不到实际标的。
- 其他渠道的格式由对应插件声明，后端按账户渠道校验，不接受通配符。规范化后重复的品种配置会被拒绝。
- 已配置品种先匹配自己的时段；未命中时用品种默认算法，不再继承账户时段。不同品种的时段可以相同，每个品种内部不能重叠。
- 所有品种用同一次调仓开始时间选择完整配置并冻结；清仓继续使用账户清仓算法，执行总超时仍为账户共用。
- 启用品种配置后，执行标的无法解析为渠道支持的品种时明确报错，不会静默使用账户默认算法；合法但没有单独配置的品种仍使用账户默认。期货代码校验使用本地品种表；掘金及其他插件的格式校验不代表查询柜台确认标的存在。

API 的 `product_algorithms` 是按品种的完整替换映射，省略字段保留已有设置，提交 `{}` 清空。例如：

```json
{
  "product_algorithms": {
    "ag": {
      "algorithm": {"method": "TWAP", "params": {"slices": 3}},
      "algorithm_schedule": [
        {"start": "21:00", "end": "02:30", "algorithm": {"method": "TWAP", "params": {"slices": 8}}}
      ]
    }
  }
}
```

## 参数要结合算法语义看

以 TWAP 为例：

```python
algorithm = {
    "method": "TWAP",
    "params": {
        "total_duration": 300,
        "slices": 10,
        "price_strategy": "ACTIVE",
        "max_wait_seconds": 60,
    },
}
```

这组参数计划每 30 秒执行一片，每片最多等待 `min(60, 30)` 秒。未完成的数量会滚入后续片，最后一片可能集中处理剩余数量。执行结束后仍需检查持仓和订单状态，确认是否到位。

这组配置只作参数示例，不作为实际账户的执行建议。

## 开发自定义下单算法

自定义算法通过 `register_algorithm` 注册，接收 `AlgorithmInput`，返回 `AlgorithmResult`。输入中包含单品种 `symbol`、已经规划的 `target_volume`、品种交易规则和参数；算法通过 `ExecutorProtocol` 与执行上下文交互。

在高级设置点击“添加算法目录”，进入存放脚本的文件夹。目录选择器会自动显示当前层发现的算法名称和来源脚本；没有算法或存在读取问题时，不能使用该目录。只检查当前层普通 `.py` 文件，不递归扫描子目录，不导入执行脚本，也不读取 `pyproject.toml`。脚本无需打包安装。

例如代码位于 `my-axon-algorithms/src/my_axon_algorithms/prev_vwap_open.py`，需要在选择器中进入 `src/my_axon_algorithms`。项目根目录没有直接声明算法时，会提示继续进入子文件夹。

预览通过单线程 Rust 专用识别器查找模块顶层 `@register_algorithm("名称")` 与对应的函数，支持多行参数、注释和普通字符串。名称不是直接字符串时，先展示文件和函数入口，用户点击“加载文件”后执行 Python 导入并显示实际注册算法；浏览不会解析名称依赖或执行脚本。注册器别名不属于识别范围；已安装的算法包仍可使用折叠的“按模块名添加（高级）”。

确认目录后保存并重启，系统加载当前层声明算法的脚本，并检查注册结果及来源。静态发现不代表脚本已成功加载，依赖缺失或运行时注册错误会明确报错。界面根据实际注册元数据中的参数模型、渠道和槽位显示参数并筛选可选算法。

编写算法时需要处理以下问题：

1. 当前渠道的订单参数、开平仓和数量规则。
2. 未知持仓、缺少行情、未完成订单和终态处理。
3. 协作式终止、超时、撤单与剩余缺口。
4. 明确的 `AlgorithmResult`、订单与成交证据、审计事件。
5. 使用 Clock 与执行会话的等待方法，保持可测试性。

接口定义见[算法注册与协议](https://github.com/zengbin93/axile/blob/main/axile/executor/algorithms/core/base.py)，加载过程见[加载器](https://github.com/zengbin93/axile/blob/main/axile/executor/algorithms/core/loader.py)。这里列出的是接口和现有实现，尚无完整的自定义算法开发案例。
